# 프런트 입력 검증 및 레이아웃 QA 설계

## 목표

사용자가 지나치게 길거나 형식이 잘못된 값을 입력했을 때 요청 전에 정확한 필드 오류를 보여주고, 서버 오류도 이해할 수 있는 한국어 안내로 변환한다. 긴 제목·이메일·파일명·질문·피드백이 카드나 모달 밖으로 넘치지 않게 하며, 발표 녹화 화면의 10초 음성 분석 결과가 일반적인 화면 배율과 작은 화면 높이에서도 가려지지 않게 한다.

## 확정된 용어와 계약

- 회원가입 첫 필드의 사용자 용어는 `아이디`다.
- 이 값은 새 로그인 식별자가 아니라 Spring `SignupRequest.nickname`으로 전송한다.
- 로그인은 기존과 동일하게 이메일과 비밀번호를 사용한다.
- 아이디는 Spring `app_users.nickname` 및 프로필 수정 계약에 맞춰 최대 50자로 제한한다.
- 서버가 명시한 제한을 우선 적용한다.
  - 아이디·프로필 아이디: 50자
  - 발표 연습명: 128자
  - 발표 설명: 500자
  - 폴더명: 128자
  - 폴더 설명: 500자
  - 자소서·포트폴리오 제목: 50자
  - 슬라이드 핵심 내용: 500자
- 면접 연습명은 `Interview.title` 길이 100자에 맞춘다.
- 서버에 상한이 없는 이메일과 비밀번호는 각각 254자와 128자의 브라우저 입력 상한을 둔다. 최소 비밀번호 길이는 기존 8자를 유지한다.

## 입력 검증 UX

- 주요 입력은 HTML `maxlength`와 제출 전 JavaScript 검증을 함께 사용한다.
- 사용자가 한도를 넘겨 붙여넣으려 한 경우, 입력을 조용히 자르는 데서 끝내지 않고 `최대 N자까지 입력할 수 있습니다`를 표시한다.
- 글자 수가 중요한 여러 줄 입력과 제목 입력에는 `현재 글자 수 / 최대 글자 수`를 표시한다.
- 오류 문구는 필드 바로 아래에 표시하고 `role="alert"` 또는 접근성 연결을 제공한다.
- 빈 값, 형식 오류, 최소 길이, 최대 길이, 비밀번호 불일치를 서로 다른 문구로 구분한다.
- 첫 오류 필드로 포커스를 이동해 사용자가 수정 위치를 바로 찾게 한다.
- 서버 오류는 가능한 경우 오류 코드로 필드에 매핑한다.
  - `40901`: 이미 사용 중인 아이디
  - `40902`: 이미 가입된 이메일
  - `40003`: 회원가입 입력값 확인
  - `40011`: 현재 비밀번호 불일치
  - `40012`: 새 비밀번호 조건 불충족
- 서버의 영문 내부 메시지는 그대로 사용자에게 노출하지 않는다.

## QA 대상 화면

- 인증: 회원가입, 로그인, 계정 찾기
- 마이페이지: 아이디·프로필 이미지 수정, 비밀번호 변경, 자소서·포트폴리오 등록
- 연습 준비: 폴더 생성, 발표 설정, 면접 설정, 슬라이드 핵심 내용
- 발표 녹화: 실시간 발화, 10초 WAV 분석 결과, 오류 안내

FAQ 검색처럼 저장되지 않는 보조 입력은 레이아웃 안정성만 확인하고 도메인 검증 대상에서는 제외한다.

## 긴 문자열 레이아웃 정책

- flex/grid 자식에는 필요한 곳마다 `min-width: 0`을 적용한다.
- 제목과 짧은 메타데이터는 화면 목적에 따라 1~2줄 말줄임을 사용한다.
- 사용자가 내용을 확인해야 하는 본문·오류·질문·피드백은 `overflow-wrap: anywhere`로 줄바꿈하고 숨기지 않는다.
- 이메일, URL, 확장자 없는 긴 파일명처럼 공백 없는 문자열도 컨테이너 밖으로 나가지 않게 한다.
- 버튼과 배지는 내용 때문에 부모 폭을 밀어내지 않도록 최대 폭과 말줄임을 적용한다.
- 50자 제목을 포함한 경계값과 한글·영문 무공백 문자열을 별도 테스트한다.

## 발표 녹화 패널

- 현재 후반 CSS의 `record-rail { overflow: hidden }`이 초기 `overflow-y: auto`를 덮어써 하단 분석 상태를 자르는 것이 핵심 원인이다.
- 데스크톱에서도 왼쪽 레일 자체에 세로 스크롤을 허용한다.
- 실시간 발화 영역은 제한된 높이 안에서 내부 내용을 갱신하되, 10초 분석 상태와 오류 영역은 레일 하단에서 사라지지 않게 한다.
- 작은 화면 높이 및 100% 배율에서 마지막 분석 카드까지 키보드와 휠로 접근 가능해야 한다.
- 모바일 레이아웃의 페이지 스크롤과 중복 스크롤이 생기지 않도록 기존 980px 분기를 유지한다.

## 테스트와 완료 조건

- 검증 유틸 단위 테스트: 빈 값, 경계값, 초과값, 이메일, 비밀번호, 오류 코드 매핑.
- 뷰 테스트: 아이디 라벨·`nickname` payload, `maxlength`, 글자 수, 초과 안내, 첫 오류 포커스.
- 레이아웃 회귀 테스트: 긴 제목/이메일/파일명용 클래스와 발표 레일 스크롤 가능 상태.
- 기존 면접·발표 흐름의 전체 Vitest 통과.
- Vite 프로덕션 빌드 성공.
- 실제 렌더링 QA: 회원가입 데스크톱/모바일, 긴 문자열 카드, 발표 녹화 1920×1080 및 높이가 작은 뷰포트에서 오버플로·가림·콘솔 오류 확인.

## 범위 제한

- Spring 스키마나 인증 방식을 변경하지 않는다.
- 아이디 로그인 기능을 새로 만들지 않는다.
- 서버에 없는 중복 확인 API를 가짜 성공으로 만들지 않는다.
- 사용자 입력을 임의로 변형해 저장하지 않고, 허용 범위를 초과하면 저장을 막고 이유를 안내한다.
