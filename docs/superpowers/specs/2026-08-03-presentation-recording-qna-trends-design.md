# 발표 녹화·질의응답·폴더·성장 추이 보완 설계

## 목표

면접 녹화 코드는 변경하지 않으면서 발표 흐름의 폴더 표시, 분석 시작 시점, STT, 질의응답 저장을 면접에서 검증된 동작에 맞춘다. 성장 추이는 기록이 6회 미만이어도 계산 가능한 데이터를 최대한 보여준다.

## 범위와 제약

- 변경 범위는 `frontend-vue-main`이다.
- `InterviewRecordView.vue`와 면접 데이터 흐름은 수정하지 않는다.
- 발표 녹화와 발표 질의응답의 STT는 면접 구현을 참조하되 발표 화면 내부에 각각 독립적으로 둔다.
- 리포트 공통 컴포넌트나 녹화 공통 계층을 새로 만들지 않는다.
- 폴더 유형의 실제 DB 저장·서버 필터링은 후속 백엔드 작업으로 남긴다.

## 1. 연습 폴더 유형 표시

발표 진입은 `GET /api/v1/practice-folders?type=presentation`, 면접 진입은 `GET /api/v1/practice-folders?type=interview`를 사용한다. 폴더 생성에도 현재 진입 유형을 `type`으로 전송한다.

프런트는 응답을 정규화한 뒤 현재 진입 유형과 일치하는 폴더만 렌더링한다. 현재 Spring은 요청받은 유형을 응답에 반영하지만 이를 DB에 저장하지 않으므로, 프런트에서 새로 생성한 폴더는 계정별 `folderId -> type` 매핑도 로컬에 보존한다. 매핑이 있는 폴더는 저장된 유형을 우선하고, 매핑이 없는 기존 폴더는 서버 응답 유형을 사용한다. 따라서 이번 범위에서는 같은 브라우저에서 생성한 폴더를 정확히 분리하며, 기존 폴더의 완전한 분리와 다른 기기 동기화는 후속 서버 필터링이 필요하다.

폴더 생성과 목록 조회의 경합을 막기 위해 생성 시작 시 이전 목록 요청을 무효화하고, 생성 성공 후 현재 유형의 목록을 다시 조회한다. 재조회 결과에 방금 생성한 폴더가 아직 없으면 생성 응답을 목록에 유지한다. 생성된 폴더는 선택 상태로 유지한다.

## 2. 발표 분석 시작 시점

발표 녹화 화면 진입 시에는 카메라 미리보기와 MediaPipe 모델 준비만 수행한다. 시선·자세 표본 수집은 `발표 시작하기`가 성공한 뒤 시작한다.

시작 전에는 시선 이탈 횟수와 자세 지표를 `--`로 표시한다. 발표 종료 또는 화면 이탈 시 분석을 중단한다. 면접의 분석 시작 시점과 동일한 사용자 의미를 갖되 발표 파일 안에서 구현한다.

## 3. 발표 STT

발표 STT는 면접의 Web Speech API 수명주기를 발표 화면 안에 독립적으로 구현한다.

- `SpeechRecognition` 또는 `webkitSpeechRecognition` 인스턴스 한 개를 유지한다.
- `lang = 'ko-KR'`, `continuous = true`, `interimResults = true`를 사용한다.
- 한 이벤트에 포함된 여러 중간 결과를 이어 붙인다.
- 최종 문장은 배열에 누적하고 중간 문장도 항상 자막에 함께 표시한다.
- 브라우저가 인식 세션을 종료하면 발표가 진행 중인 동안 자동 재시작한다.
- 발표 시작·일시정지·재개·종료에 맞춰 활성 상태를 제어한다.
- 최종 문장이 확정될 때 기존 슬라이드 번호와 발표 경과 시각을 기록한다.

면접 STT 파일과 공통 composable은 변경하지 않는다.

## 4. 발표 질의응답

설정에서 질의응답 모드를 켜면 발표 생성 요청의 `aiQnaEnabled`에 반영한다. 질문 생성은 발표 발화가 확정된 뒤에만 가능하므로 발표 `complete` 성공 직후 실행한다.

흐름은 다음과 같다.

1. 발표 완료 API 성공
2. `POST /api/v1/presentations/{presentationId}/presentation-questions/generate`
3. 질문 화면 이동
4. 필요 시 `GET /api/v1/presentations/{presentationId}/presentation-questions`
5. 질문별 음성 답변을 STT 전문으로 확정
6. `POST /api/v1/presentation-questions/{questionId}/answers`
7. 저장 성공 후 다음 질문으로 이동
8. 마지막 답변 저장 후 발표 리포트로 이동

답변 요청 본문은 타임스탬프 없이 다음 형식만 사용한다.

```json
{
  "answer": "해당 질문에 답한 전체 STT 전문"
}
```

답변 저장 중에는 중복 제출을 막는다. 실패하면 현재 질문과 STT 전문을 보존하고 오류와 재시도 동작을 제공한다. 성공하기 전에는 질문을 완료 처리하거나 다음 질문으로 이동하지 않는다.

## 5. 성장 추이의 부족한 기록 처리

응답의 `practices`, `lateTrend`, `speech`에서 존재하는 값은 기록 수와 관계없이 표시한다.

- 0회: 연습 기록이 없다는 빈 상태를 표시한다.
- 1~3회: `lateTrend`는 `최근 N회 평균`으로 표시하고 실제 N개의 점수 그래프와 존재하는 음성 참고 지표를 보여준다.
- 4~5회: 최근 3회와 나머지 이전 1~2회를 비교하며 화면 문구에 실제 비교 개수를 표시한다.
- 6회 이상: 이전 3회와 최근 3회를 비교한다.

비교 기준이 부족한 항목은 값을 숨기지 않는다. 현재 값은 표시하고 증감 영역에 `비교할 이전 기록이 부족해요`를 회색 글자와 회색 점선 테두리로 표시한다.

6회 미만의 강점과 약점은 단위가 동일한 최근 `contentScore`, `videoScore`, `voiceScore` 평균만 비교한다. 가장 높은 영역은 `최근 연습에서 상대적으로 강한 영역`, 가장 낮은 영역은 `우선 점검할 영역`으로 표현하며 절대적인 좋음·나쁨으로 단정하지 않는다.

## 오류 처리

- 폴더 조회 실패는 기존 API 오류를 그대로 표시하고 목 데이터로 대체하지 않는다.
- STT 미지원·권한 오류는 발표를 중단하지 않으며 자막 미지원 안내를 표시한다.
- 질문 생성 실패 시 질문 화면으로 이동하지 않고 재시도 가능한 오류를 표시한다.
- 질문 답변 저장 실패 시 현재 질문과 답변 전문을 유지한다.
- 분석 모델 로드 실패는 시선·자세 없이 발표를 계속할 수 있게 한다.

## 검증

- 발표·면접 폴더 요청에 올바른 `type`이 포함되고, 로컬 유형이 확정된 다른 유형 폴더가 렌더링되지 않는지 검증한다.
- 생성 중인 목록 요청이 생성 결과를 덮어쓰지 않는지 비동기 회귀 테스트를 작성한다.
- 발표 시작 전에는 Face Analysis가 시작되지 않고 시작 버튼 성공 후 시작되는지 검증한다.
- 발표 STT가 면접과 같은 final/interim 누적 및 자동 재시작 동작을 갖는지 검증한다.
- 질문 생성 경로와 질문별 `{ answer }` POST 계약을 검증한다.
- 답변 API 실패 시 질문·전문이 유지되고 성공 시에만 다음 질문으로 이동하는지 검증한다.
- 1회, 3회, 4~5회, 6회 데이터에서 성장 추이의 값·문구·점선 부족 상태를 검증한다.
- 전체 `npm test`, `npm run build`와 로컬 렌더링을 확인한다.
