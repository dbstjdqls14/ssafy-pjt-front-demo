# 프런트 발표·면접 세션 안정화 설계

## 1. 목표와 품질 수준

이 작업은 개별 화면의 `disabled` 조건을 추가하는 QA 패치가 아니다. 발표와 면접의 진행 상태, 비동기 작업, 미디어 수집, API 요청을 명시적으로 제어하여 다음 문제를 구조적으로 제거한다.

- TTS 중 질문 이동·종료 연타로 빈 오디오가 complete에 전송되는 문제
- 발표·면접 시작/종료/뒤로 가기/권한 변경이 동시에 실행되는 문제
- 같은 비동기 API가 중복 호출되는 문제
- 화면의 비활성화 조건과 클릭 핸들러 조건이 서로 다른 문제
- 브라우저 이력과 sessionStorage 때문에 종료된 세션이 다시 시작되는 문제
- API 필드의 의미가 달라도 normalizer가 정상 데이터처럼 처리하는 문제
- 이름을 ID처럼 사용하여 동일 이름 항목이 함께 선택되는 문제

목표는 실제 서비스 품질이다. 프런트만으로 완전히 해결할 수 없는 서버 세션 취소와 complete 멱등성은 임시 방어와 운영 수준 해결책을 구분한다.

## 2. 설계 원칙

### 화면은 분리하고 하위 기능만 공유한다

- 면접 화면과 발표 화면의 Vue 컴포넌트 및 UI는 별도로 유지한다.
- 면접 리포트와 발표 리포트도 별도로 유지한다.
- 공통화 대상은 순수하거나 저수준인 기능으로 제한한다.
  - 배타적 명령 실행기
  - 미디어 권한 감시
  - 녹화 결과 검증
  - PCM WAV 수집
  - API 오류 변환
  - 숫자·시간 포맷

### 이름과 제목은 식별자가 아니다

- 선택, `key`, 수정, 삭제, 라우팅은 서버 ID만 사용한다.
- 이름과 제목은 표시와 검색에만 사용한다.
- 서버 ID가 없는 항목에 임시 ID를 만들어 실제 엔티티처럼 취급하지 않는다.

### UI와 명령 핸들러는 같은 권한 판정을 사용한다

- `:disabled`와 클릭 핸들러가 동일한 `canXxx` computed를 사용한다.
- 자동 타이머, 키보드, 브라우저 이벤트도 같은 명령 함수를 호출한다.
- 비활성화는 시각적 방어일 뿐이며 핸들러에서도 다시 검사한다.

## 3. 세션 상태 모델

발표와 면접은 각자의 세션 controller를 갖는다. 공통 UI controller 하나를 만들지 않는다.

| 상태 | 의미 | 허용 명령 |
| --- | --- | --- |
| `READY` | 장치와 데이터 준비 완료 | 시작, 장치 변경, 뒤로 가기 |
| `COUNTDOWN` | 시작 카운트다운 | 취소 |
| `PROMPT_PLAYING` | 질문 TTS 재생 | TTS 취소 |
| `CAPTURING` | 정상 녹화·녹음 | 다음, 스킵, 일시정지, 종료 |
| `TRANSITIONING` | 질문/슬라이드 전환 중 | 없음 |
| `PAUSED` | 사용자 일시정지 | 재시작, 종료 |
| `DEVICE_BLOCKED` | 필수 장치 권한 또는 track 상실 | 권한 재요청, 연습 종료 |
| `FINALIZING` | 파일 flush·stop·검증·complete 준비 | 없음 |
| `ANALYZING` | 서버 분석 및 리포트 대기 | 허용된 재시도, 이탈 경고 |
| `COMPLETED` | 리포트 생성 완료 | 리포트 이동 |
| `FAILED` | 복구 가능한 실패 | 같은 자료로 재시도, 종료 |

boolean 조합으로 상태를 추론하지 않는다. `started && !paused && !speaking` 같은 분산 조건을 상태 전이로 교체한다.

## 4. 중요 명령 상호 잠금

각 화면에는 한 번에 하나의 중요 명령만 실행하는 배타적 실행기가 필요하다.

```js
const pendingAction = ref(null)

const runExclusive = async (name, action) => {
  if (pendingAction.value) return
  pendingAction.value = name
  try {
    return await action()
  } finally {
    pendingAction.value = null
  }
}
```

실제 구현에서는 controller가 상태 전이 검증도 담당한다. 1초 잠금은 배타적 실행을 대신하지 않고 전환 완료 후 더블 클릭을 막는 보조 수단으로만 사용한다.

### 주요 화면별 잠금

- 폴더/설정
  - 목록 조회 중 선택·다음 비활성화
  - 생성 요청 중 탭 변경·중복 생성·다음 비활성화
  - 자료 업로드/재사용 요청 중 이전·다음·모드 변경 비활성화
- 장치 확인
  - 권한 요청 중 요청 버튼과 다음 비활성화
  - 카메라와 마이크가 모두 준비되어야 다음 활성화
- 녹화
  - 카운트다운, TTS, 전환, 권한 차단, 종료 중 다음·스킵·종료 비활성화
  - 사용자가 일시정지했을 때 질문/슬라이드 전환 비활성화
  - 장치 복구 중 재시작·종료 연타 차단
- Q&A
  - 답변 저장 중 다음 질문·스킵·최종 종료 비활성화
  - 질문별 답변 POST가 끝나기 전에 다음 질문으로 이동하지 않음
- 분석
  - complete 또는 폴링 중 재시도 중복 실행 방지
  - 나가기·새로고침은 경고 후에만 허용
- 문서·프로필
  - 저장/삭제 중 같은 항목의 다른 동작 비활성화

## 5. 면접 TTS와 질문 전환

### 확인된 현재 문제

`InterviewRecordView.vue`는 TTS 시작 시 STT, 전체 오디오 레코더, PCM 수집기를 정지한다. 그러나 다음/종료 조건은 `isSpeaking`을 검사하지 않고 `stopTts()`도 정지시킨 레코더를 복구하지 않는다.

### 수정 설계

- `PROMPT_PLAYING` 중 다음 질문, 스킵, 종료를 모두 막는다.
- `openSegment()`와 `actuallyStart()`는 비동기 전환 명령으로 실행한다.
- 실제 전환이 끝날 때까지 `TRANSITIONING`을 유지한다.
- 전환 완료 뒤 최소 1초간 재클릭 잠금을 둔다.
- 자동 1분 전환도 `canAdvance`를 통과해야 한다.
- 오래된 TTS `onend`/`onerror`는 `runId`로 무효화한다.
- `stopTts()`는 TTS가 소유한 정지만 해제한다.

### pause 소유권 분리

pause 원인을 하나의 boolean으로 관리하지 않는다.

- `USER_PAUSE`
- `TTS_GATE`
- `DEVICE_BLOCKED`
- `FINALIZING`

TTS가 끝나도 `USER_PAUSE`나 `DEVICE_BLOCKED`가 남아 있으면 녹음과 STT를 재개하지 않는다.

### 권장 미디어 처리

- WebM 세션 recorder의 출력 stream identity는 유지한다.
- TTS 중에는 마이크 입력 gain을 0으로 만들어 무음 구간을 기록한다.
- Chrome STT와 10초 PCM 분석만 일시 중단한다.
- TTS 종료 후 PCM, STT 순서로 복구한다.

이 방식은 MediaRecorder를 질문마다 pause/resume하여 빈 파일이나 깨진 컨테이너가 생기는 위험을 줄인다.

## 6. complete 종료 장벽

발표와 면접의 complete는 다음 순서를 모두 통과한 뒤 한 번만 실행한다.

1. 종료 명령 배타 잠금
2. TTS 취소 및 종료 확인
3. 현재 STT final 결과 반영
4. 현재 질문/슬라이드 구간 닫기
5. 마지막 10초 미만 PCM flush
6. 진행 중인 오디오 분석 요청 정리
7. MediaRecorder stop 완료 대기
8. WAV/WebM Blob 검증
9. request JSON 검증
10. complete 1회 호출
11. 성공 후 분석 화면 이동

검증 실패 시 complete를 호출하지 않는다.

- 녹음 시간이 0 이하
- 필수 Blob 없음
- Blob 크기가 최소 기준 미만
- MIME 타입 불일치
- recorder가 아직 `recording` 또는 `paused`
- 진행 중인 flush/upload가 남음

프런트는 동일 탭 내 `completePromise`로 중복 호출을 막는다. 새로고침·다중 탭까지 보장하려면 백엔드 complete 멱등성 또는 서버 상태 검사가 필요하다.

## 7. 미디어 권한과 실제 장치 종료

- 카메라와 마이크 권한 상태를 분리한다.
- 어느 한 장치만 권한을 잃어도 다른 장치 미리보기는 유지한다.
- 필수 장치 하나라도 사라지면 전체 세션 분석은 `DEVICE_BLOCKED`로 동결한다.
- 화면을 어둡게 하고 누락 장치, 권한 재요청, 연습 종료를 표시한다.
- 브라우저 권한은 코드로 강제 허용할 수 없으므로 `getUserMedia()` 재요청과 설정 안내를 제공한다.
- 내부 장치 끄기는 `track.enabled=false`가 아니라 source track을 실제 `stop()`한다.
- 녹화 출력은 canvas video와 Web Audio destination으로 고정하여 source track 교체가 WebM을 깨뜨리지 않게 한다.
- 발표 재시작 전에는 카메라와 마이크가 다시 켜진다는 확인 문구를 보여준다.
- 면접에는 새로운 일시정지 UI를 추가하지 않는다.

## 8. 브라우저 이력과 세션 수명

- 발표 녹화, 면접 녹화, 발표 분석, 면접 분석에 route leave guard를 둔다.
- SPA 뒤로 가기는 앱 확인 모달을 사용한다.
- 새로고침, 탭 닫기, 주소 이동은 `beforeunload` 기본 경고를 사용한다.
- 사용자가 이탈을 확정하면 미디어, TTS, STT, 타이머, 요청 큐를 정리하고 로컬 active session을 제거한다.
- sessionStorage에는 서버 ID만 남고 Blob/File이 사라지는 반쪽 세션을 복원하지 않는다.
- 백엔드 cancel/abandon API가 없으면 서버의 미완료 Practice는 제거할 수 없다. 프런트 정리는 임시 해결이며 운영 수준에서는 취소 API가 필요하다.

## 9. API 계약과 데이터 정확성

최신 `backend-spring-develop`의 지정 커밋을 단일 기준으로 사용한다.

- endpoint별 URL, 요청 DTO, 응답 DTO, nullable, ID 의미, 오류 코드를 고정한다.
- endpoint별 strict adapter를 둔다.
- 여러 후보 필드 fallback이 계약 오류를 숨기지 않게 한다.
- 400/401/403/409/422를 정상 데이터나 mock으로 대체하지 않는다.
- 사용자에게 표시되는 오류는 서버의 필드 오류 위치와 연결한다.

### 폴더

- 내 기록은 `/api/v1/practice-folders/archive` 계약을 사용한다.
- 동일 이름 폴더 선택은 `folder.id`로 구분한다.
- 오른쪽 상세에는 폴더 이름과 설명만 표시한다.
- 화면의 연습 횟수는 전체 Practice 수가 아니라 리포트 생성 완료 수여야 한다.
- 현재 Spring의 `countByFolder_Id()`는 중도 이탈 Practice도 포함하므로 운영 수준에서는 `completedReportCount`가 필요하다.
- 백엔드 계약 전에는 잘못된 횟수를 표시하지 않는다.

### 기존 발표 자료

- `GET /api/v1/practice-folders/{folderId}/presentation-practices`
- `POST /api/v1/presentations/reuse`
- 자료 선택 모드는 `none | upload | reuse | existing-session` 중 하나만 활성화한다.
- 이전/다음 이동 시 다른 모드의 file, ID, slide 상태를 명시적으로 정리한다.

## 10. 발표 Q&A 흐름

### Q&A OFF

`발표 마치기 → complete → 분석 대기 → 리포트 조회`

### Q&A ON

`발표 마치기 → 질문 생성 → Q&A → 질문별 답변 POST/스킵 → 발표 최종 종료 → complete → 분석 대기 → 리포트 조회`

- 질문 답변 저장 중 다음·스킵·종료를 막는다.
- 개별 질문 스킵은 빈 답변으로 명확히 기록한다.
- 모든 질문을 스킵한 경우 리포트에 Q&A 평가가 생성되지 않음을 종료 전에 안내한다.
- 등록된 답변이 없는 질문 피드백은 리포트에서 숨긴다.

## 11. 실시간 음성 분석과 추임새 누적

- 발표와 면접이 동일한 말하기 속도 계산 함수와 동일한 단위를 사용한다.
- 전체 누적 발화량을 전체 경과 시간으로 나누는 방식은 초반 침묵 때문에 계속 `느림`으로 고정될 수 있으므로 최근 확정 발화 구간을 기준으로 계산한다.
- TTS 재생 구간과 사용자 일시정지 구간은 분모와 발화량에서 모두 제외한다.
- 화면에는 `느림 | 보통 | 빠름`과 한국어 어절 기반 값을 표시하고, 리포트 용어도 동일하게 맞춘다.
- 10초 분석 응답은 `sequence` 기준으로 한 번만 반영한다. 재시도 응답과 늦게 도착한 응답이 추임새 횟수를 중복 증가시키지 않게 한다.
- 진행 중인 청크와 마지막 flush의 완료 여부를 session controller가 추적한다.
- 추임새, 침묵, WPM/어절 단위는 API 원본 단위와 화면 표시 단위를 adapter에서 명시적으로 변환한다.

## 12. 인증·문서·분석 진입 정책

- 로그인하지 않은 사용자가 발표·면접 진입을 시도하면 `로그인이 필요한 서비스입니다.`를 표시하고 로그인 화면으로 이동한다.
- 소셜 로그인 UI와 mock 동작은 제거한다.
- 비밀번호 찾기/재설정 기능은 제거하고 합의된 아이디 찾기만 유지한다.
- 401은 세션을 정리한 뒤 로그인으로 이동하며, 중복 로그인·만료 응답은 서버 계약에 맞는 메시지를 표시한다.
- 자소서·포트폴리오 저장/삭제는 실제 API 성공 후 목록을 갱신하고, 요청 중 같은 항목의 중복 조작을 막는다.
- 분석 화면을 여러 탭에서 열어도 complete를 다시 시작하지 않는다. 서버 분석 상태를 조회하고 이미 진행 중이면 관찰만 한다.
- 분석 terminal status와 timeout을 처리하여 사용자가 무기한 기다리지 않게 한다.

## 13. 리포트와 내 기록

- 발표와 면접 리포트 화면 구현은 분리하여 기존 면접 UI에 영향을 주지 않는다.
- 내 기록에서 발표는 `presentationId`, 면접은 `interviewId`로 해당 리포트 API를 호출한다.
- 서버 점수가 존재하면 정확한 필드를 표시하고, 전체 화면을 `데이터 없음`으로 대체하지 않는다.
- 이전 기록이 부족한 성장 추이 항목만 점선·회색 결측 카드로 표시한다.
- 답변이 없는 질문은 `답변하지 않았어요` 상태로 순서를 유지하되 상세 피드백은 숨긴다.
- 자막 또는 발화 구간을 클릭하면 해당 timestamp로 영상이 이동한다.
- 발표 리포트의 추임새 marker, 음성 그래프, 몸짓 그래프는 API timestamp를 기준으로 표시한다.
- 30초 미만 리포트는 점수 카드 대신 짧은 연습 안내 카드를 표시하며 발표/면접 문구를 구분한다.

## 14. UI·검증·반응형 안정화

- 연습명 15자, 폴더명 20자, 사용자 ID 20자, 목표 발표 시간 1~30분을 단일 상수로 관리한다.
- IME 조합 입력에서도 최종 길이가 제한을 넘지 않게 한다.
- 긴 이름·닉네임·제목은 한 줄 말줄임으로 처리한다.
- 점수와 비율은 용도별 소수점 자릿수를 고정한다.
- PDF만 허용하고 확장자와 실제 MIME을 함께 검증한다.
- 작은 파일은 MB `0.0` 대신 KB로 표시한다.
- 수정하는 화면부터 전역 selector 의존을 줄이고 페이지 root 범위로 CSS를 제한한다.
- 대표 viewport와 배율에서 헤더, 폴더, 녹화, Q&A, 분석, 리포트를 검증한다.
- 자소서 추출 내용처럼 같은 소제목이 중복 표시되지 않게 빈 상태·로딩 상태·성공 상태의 소유 컴포넌트를 하나로 정한다.
- FAQ 검색 조건과 결과 없음 상태를 명확히 표시한다.

## 16. 검증 기준

### 상태 전이

- TTS 중 다음·스킵·종료가 실행되지 않는다.
- 자동 전환과 수동 클릭이 겹쳐도 질문이 한 번만 이동한다.
- 종료 연타에도 complete가 한 번만 호출된다.
- 권한 상실 중 녹화 재개와 complete가 실행되지 않는다.
- 진행 중인 PCM 요청과 Blob 생성이 끝나기 전에 complete가 실행되지 않는다.

### 브라우저

- TTS 중 다음·종료 연타
- 마지막 질문 TTS 중 종료
- 카메라만 제거, 마이크만 제거, 둘 다 제거
- 뒤로 가기 후 재진입과 새로고침
- Q&A ON/OFF와 전체 질문 스킵
- 분석 화면 다중 탭과 complete 중복 방지
- 실시간 말하기 속도 `느림 | 보통 | 빠름` 경계값
- 10초 청크 재시도·순서 뒤바뀜·마지막 flush 시 추임새 중복 방지
- 80/100/125/150% 배율 및 대표 viewport

### API

- 요청 경로, DTO, multipart part 이름
- report 없는 연습을 report route로 열지 않음
- folder ID 기반 선택과 completed report count 의미
- complete 중복과 오류 응답 처리

## 17. 범위 밖이지만 필요한 백엔드 계약

- 미완료 Practice cancel/abandon API
- complete 멱등성 또는 세션 상태 검사
- 폴더별 `completedReportCount`
- 분석 진행 단계 또는 명확한 terminal status

이 항목이 추가되기 전 프런트 방어는 데이터 유실과 중복 동작을 줄일 수 있지만, 서버에 남은 미완료 세션까지 완전히 제거하지는 못한다.
