# 발표·면접 자료 재사용 및 미디어 세션 복구 설계

## 목표

발표의 기존 자료 선택을 서버 API 기반으로 일관되게 만들고, 발표·면접에서 카메라와 마이크 권한 및 실제 장치 점유 상태를 독립적으로 관리한다. 브라우저 권한 철회나 이탈로 세션이 손상될 때는 녹화를 계속한 것처럼 처리하지 않고 즉시 동결한 뒤 취소 또는 처음부터 재시작하도록 안내한다.

## 품질 수준과 제약

- 서버에 저장된 기존 발표 자료 조회와 복사는 현재 Spring API로 서비스 품질 구현이 가능하다.
- 카메라·마이크를 실제로 해제한 뒤 하나의 WebM 녹화를 이어 가는 기능은 Chrome 계열에서 `canvas.captureStream()`과 Web Audio의 `MediaStreamDestination`을 사용하는 방식으로 구현한다. 프로젝트가 이미 Chrome STT를 전제로 하므로 지원 범위와 일치한다.
- 브라우저 주소창 설정에서 사용자가 권한을 `차단`한 경우 프런트가 권한을 다시 허용할 수 없다. 프런트는 세션을 동결하고 권한 설정 방법 및 취소·처음부터 재시작만 제공한다.
- 현재 Spring에는 시작된 발표·면접을 취소하는 API가 없다. 따라서 이번의 세션 취소는 프런트 상태를 폐기해 같은 로컬 세션 재진입을 막는 임시 조치다. 이미 생성된 미완료 서버 Practice를 삭제하거나 취소 상태로 바꾸지는 못한다.
- 발표와 면접 화면은 각각 독립된 뷰 구조를 유지한다. 공통화하는 것은 장치·녹화의 브라우저 저수준 처리뿐이다.

## 확인된 현재 원인

### 기존 발표 자료

- 서버 목록 API `GET /api/v1/practice-folders/{folderId}/presentation-practices`와 복사 API `POST /api/v1/presentations/reuse` 호출 코드는 존재한다.
- 그러나 선택 상태가 `stagedFile`, `sourceFile`, `reusedSource`, `appliedReuseId`, 기존 `sessionId`로 분산되어 있다.
- 새 파일 업로드 후 이전 화면으로 돌아가 기존 자료를 선택하거나 반대 순서로 이동하면, 이전 모드의 상태가 일부 남아 표시 또는 제출 분기가 중복될 수 있다.
- 재사용 후보 응답에 같은 `presentationId`가 중복되더라도 현재는 그대로 표시한다.

### 권한과 장치

- 카메라와 마이크를 한 번의 `getUserMedia({ video, audio })`로 요청하므로 한 권한만 실패해도 전체 스트림이 사라진다.
- 화면의 장치 버튼은 `MediaStreamTrack.enabled`만 변경한다. 영상과 음성은 가려지지만 트랙이 종료되지 않아 카메라 불빛과 브라우저 장치 사용 표시가 남는다.
- 녹화 중 직접 `track.stop()`을 호출하면 현재 MediaRecorder의 트랙 집합이 깨져 하나의 WebM을 안정적으로 완성할 수 없다.
- 발표에는 로컬 상태 기반 이탈 경고가 있지만, 면접과 재진입 상태에는 동일한 보호가 없고 서버에는 취소 API가 없다.

## 대안 검토

### 1. `enabled=false` 유지

- 장점: 기존 MediaRecorder와 WAV 수집을 거의 바꾸지 않는다.
- 단점: 실제 장치를 해제하지 않아 사용자의 핵심 요구를 충족하지 못한다.
- 결론: 사용하지 않는다.

### 2. 장치를 끌 때 MediaRecorder를 종료하고 WebM 조각을 단순 연결

- 장점: 구현량이 비교적 작고 물리 장치를 실제 해제할 수 있다.
- 단점: WebM 컨테이너 Blob 단순 연결은 브라우저·플레이어에 따라 첫 조각 이후가 재생되지 않을 수 있어 서비스 품질이 아니다.
- 결론: 사용하지 않는다.

### 3. 고정 녹화 스트림 브리지 사용 — 채택

- MediaRecorder에는 수명 동안 변하지 않는 가상 비디오·오디오 트랙을 제공한다.
- 실제 카메라 프레임은 canvas에 그려 가상 비디오 트랙으로 보내고, 실제 마이크는 Web Audio source를 destination에 연결해 가상 오디오 트랙으로 보낸다.
- 장치를 끄면 실제 source track을 `stop()`하고 canvas는 빈 화면, audio destination은 무음으로 유지한다.
- 다시 켜면 해당 종류만 `getUserMedia`로 재요청하고 같은 가상 출력에 연결한다.
- 장점: 카메라 불빛과 실제 마이크 점유를 해제하면서도 complete에 보낼 WebM은 하나로 유지된다.
- 단점: Chrome 계열 브라우저 전제이며 브리지 수명주기 테스트가 추가로 필요하다.

## 1. 기존 발표 자료 API 흐름

### 서버 목록

- 기존 자료 모달을 열 때마다 `GET /api/v1/practice-folders/{folderId}/presentation-practices`를 새로 호출한다.
- 목록은 응답의 `presentationId`가 있는 항목만 사용하고 `presentationId` 기준으로 중복 제거한다.
- 서버 호출 실패 시 이전 캐시를 실제 목록처럼 남기지 않고 오류 상태를 표시한다.

### 선택 상태

- 자료 모드는 `none | upload | reuse | existing-session` 중 하나만 활성화한다.
- 새 파일을 고르면 재사용 선택, 적용된 재사용 ID, 기존 세션 슬라이드를 모두 제출 대상에서 제외한다.
- 서버 자료를 고르면 로컬 File, staged file, 기존 업로드 표시를 모두 제출 대상에서 제외한다.
- 이전 버튼으로 돌아왔을 때는 현재 활성 모드 하나만 복원한다. 화면에 파일 행과 재사용 행이 동시에 나타나지 않는다.

### 복사

- 서버 자료 선택 후 다음 버튼은 `POST /api/v1/presentations/reuse`를 정확히 한 번 호출한다.
- body에는 현재 폴더·연습 설정과 선택한 `sourcePresentationId`를 보낸다.
- 성공 응답의 새 `presentationId`, `practiceId`만 현재 연습 세션으로 채택하고 슬라이드를 서버에서 다시 조회한다.
- 같은 선택으로 설정↔슬라이드 화면을 왕복할 때 이미 생성된 새 발표를 다시 복사하지 않는다.

## 2. 계정 찾기 정리

- 현재 소스에는 `/find-account`의 아이디 찾기와 비밀번호 재설정 폼이 모두 남아 있다.
- 이번 범위는 앞서 확정한 대로 로그인 화면의 비밀번호 찾기 진입과 비밀번호 재설정 탭·요청을 제거한다.
- 아이디 찾기 폼과 `/find-account` 경로는 유지한다. 로그인 화면에 아이디 찾기 진입을 새로 추가하지 않는다.

## 3. 카메라·마이크 권한 분리

- `useMediaDevices`는 카메라와 마이크의 상태를 각각 `idle | requesting | granted | denied | ended | error`로 관리한다.
- 초기 확인은 영상과 음성을 독립 요청해 한쪽 실패가 다른 쪽 미리보기를 제거하지 않게 한다.
- `requestVideo()`, `requestAudio()`, `releaseVideo()`, `releaseAudio()`, `requestRequiredDevices()`를 제공한다.
- 실제 트랙의 `ended` 이벤트와 Permissions API `change` 이벤트는 장치 종류와 원인을 함께 상위 화면에 전달한다.
- 장치 확인 화면은 카메라 거부 시에도 마이크 레벨을, 마이크 거부 시에도 카메라 영상을 유지한다.

## 4. 실제 장치 종료와 녹화 브리지

- 카메라 끄기는 실제 video track에 `stop()`을 호출해 카메라 불빛을 끈다.
- 마이크 끄기는 Chrome STT를 중단하고 실제 audio track에 `stop()`을 호출한다.
- 녹화 브리지는 실제 source stream과 MediaRecorder용 output stream을 분리한다.
- 발표의 10초 WAV 수집은 브리지의 고정 audio output을 입력으로 사용한다. 마이크가 꺼진 동안에는 무음이고, 일시정지 중에는 기존 정책대로 구간 시간에서 제외한다.
- 카메라가 꺼진 동안 canvas에는 빈 프레임을 유지하고, 녹화 화면은 `카메라가 꺼져 있습니다.` 상태를 표시한다.
- 발표 중에는 기존처럼 장치 버튼을 잠근다. 발표 일시정지 상태에서만 실제 장치를 해제할 수 있다.
- 면접은 일시정지 UI를 새로 추가하지 않는다. 진행 중 장치 버튼은 잠그며, 시작 전과 종료 후에만 실제 장치를 해제할 수 있다.

## 5. 발표 재개 확인

- 발표가 일시정지된 동안 카메라 또는 마이크가 해제된 상태에서 `다시 시작`을 누르면 즉시 재개하지 않는다.
- 확인 모달에 `다시 시작하면 카메라와 마이크가 다시 켜집니다.`를 표시한다.
- 사용자가 확인하면 필요한 장치만 다시 요청한다.
- 두 장치가 모두 준비된 뒤 video preview, 브리지 source, MediaPipe, Chrome STT, PCM 수집, MediaRecorder, 타이머 순으로 재개한다.
- 한 장치라도 준비되지 않으면 일시정지 상태를 유지하고 권한 안내를 표시한다.

## 6. 외부 권한 철회 시 동결

- 발표·면접 도중 주소창 설정, OS 설정, 장치 분리 등으로 track이 종료되면 즉시 세션을 동결한다.
- 동결 시 타이머, MediaRecorder, PCM 수집, STT, MediaPipe를 더 진행하지 않는다.
- 비디오만 철회되면 기존 오디오 상태는 표시상 유지하고, 오디오만 철회되면 기존 비디오 미리보기는 유지한다. 다만 분석 계약의 완전성을 위해 세션 전체는 동결한다.
- 차단 모달은 누락 장치, 권한을 다시 허용하는 방법, `연습 취소`, `처음부터 다시 시작`을 제공한다.
- 권한을 허용해도 손상 가능성이 있는 현재 세션을 이어 붙이지 않는다. 처음부터 다시 시작은 현재 프런트 세션을 폐기하고 준비 화면으로 이동한다.

## 7. 브라우저 뒤로가기와 임시 세션 해결

- 발표 녹화, 면접 녹화, 발표 분석 중, 면접 분석 중 화면에 Vue Router 이탈 가드를 각각 둔다.
- 브라우저 뒤로가기·앞으로가기에도 커스텀 경고를 띄우고, 새로고침·탭 닫기는 브라우저 기본 `beforeunload` 경고를 사용한다.
- 경고 취소 시 현재 경로와 세션을 유지한다.
- 경고 확인 시 미디어·분석 작업을 정리하고 해당 Pinia 흐름의 `sessionId` 또는 `interviewId`를 포함한 진행 상태를 폐기한다.
- 다음 진입은 이전에 시작된 ID로 `/start`를 다시 호출하지 않고 설정 또는 자료 선택부터 새 서버 연습을 만든다.
- 이 처리는 프런트 임시 해결이다. 서버의 미완료 Practice 정리는 취소 API가 추가된 이후 별도 연결한다.

## 8. 오류 처리

- 권한 거부, 장치 없음, 장치 사용 중, 보안 컨텍스트 오류를 서로 다른 문구로 표시한다.
- 실제 장치 재연결 실패는 녹화 재개 성공처럼 처리하지 않는다.
- 기존 자료 목록 API 오류는 로컬 파일이나 이전 캐시로 대체하지 않는다.
- 서버 재사용 API 4xx는 새 presentation ID가 발급된 것처럼 상태를 변경하지 않는다.
- 세션 동결 또는 이탈 정리 중 오류가 나더라도 장치 트랙은 반드시 종료한다.

## 9. 테스트와 완료 조건

- 기존 자료 모달을 열 때 서버 목록 API가 호출되고 `presentationId` 중복이 제거되는지 검증한다.
- 업로드↔재사용↔이전 화면 왕복 후 하나의 자료 모드만 남고 재사용 POST가 한 번만 호출되는지 검증한다.
- 비밀번호 찾기 링크·탭·재설정 API 호출이 렌더링되지 않는지 검증한다.
- 카메라만 거부했을 때 마이크가, 마이크만 거부했을 때 카메라가 유지되는지 검증한다.
- 장치 버튼이 실제 track의 `stop()`을 호출하고 장치 종류별 상태를 갱신하는지 검증한다.
- 녹화 브리지 source를 해제·재연결해도 output stream의 track identity가 유지되는지 검증한다.
- 발표 재개 전 확인 모달, 권한 실패 시 일시정지 유지, 성공 시 전체 수집기 재개를 검증한다.
- 외부 track `ended` 시 발표·면접이 동결되고 안내 모달이 뜨는지 검증한다.
- 발표·면접의 브라우저 뒤로가기 취소·확인과 `beforeunload` 동작을 검증한다.
- 이탈 확인 후 같은 서버 세션 ID로 `/start`를 재호출하지 않는지 검증한다.
- 전체 Vitest, Vite 프로덕션 빌드, Chrome에서 카메라 불빛·마이크 표시·권한 철회·뒤로가기 시나리오를 검증한다.

## 비범위

- Spring 취소 API와 미완료 Practice 삭제 또는 상태 변경
- FastAPI·DB 변경
- 브라우저 사이트 권한을 프런트에서 직접 허용 또는 차단하는 기능
- Safari·Firefox의 Chrome STT 대체 구현
