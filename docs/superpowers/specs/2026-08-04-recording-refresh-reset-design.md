# 녹화 중 새로고침 복구 설계

## 목표

발표 또는 면접 녹화 중 사용자가 브라우저 새로고침을 확정하면 복구할 수 없는 MediaStream, MediaRecorder, STT 상태를 재사용하지 않는다. 프런트의 진행 중 세션 상태를 즉시 폐기하고 메인 화면으로 이동한 뒤, 새 연습을 시작하도록 1회 안내한다.

## 선택한 방식

명시적인 `active recording` 표식을 `sessionStorage`에 저장한다.

- 녹화 시작이 실제로 성공한 뒤 `presentation` 또는 `interview` 표식을 기록한다.
- 정상 완료, 사용자가 확인한 중도 종료, 스토어 초기화 시 표식을 제거한다.
- 녹화 화면이 새로 로드될 때 `PerformanceNavigationTiming.type === 'reload'`이고 해당 종류의 표식이 남아 있으면 새로고침 중단으로 판단한다.
- 해당 도메인 스토어와 공통 녹화 스토어를 초기화하고 표식을 제거한 뒤 `/`로 `replace`한다.
- 메인 화면에는 “새로고침으로 진행 중인 연습이 종료되었습니다. 새로운 연습을 시작해주세요.” 안내를 한 번만 표시한다.

스토어의 `presentationId`, `practiceId`, `interviewId` 존재 여부만으로 판단하지 않는다. 발표 자료 준비나 면접 질문 생성만 완료한 상태도 ID를 가지므로 실제 녹화 여부와 구분할 수 없기 때문이다.

## 대안과 제외 이유

1. 도메인 스토어 상태만 사용: 발표에는 `sessionStatus`가 있지만 면접에는 동일한 영속 상태가 없어 동작이 달라진다.
2. 새로고침 후 기존 녹화 재개: 브라우저 새로고침으로 MediaStream과 MediaRecorder가 종료되며 현재 complete 계약은 여러 WebM 구간의 안전한 병합을 지원하지 않는다.
3. 서버 취소 API 호출: 현재 백엔드 계약에 취소 API가 없고 이번 변경 범위는 프런트로 제한한다.

## 예외 동작

- 녹화 시작 전 새로고침: 활성 표식이 없으므로 현재 설정 화면을 유지한다.
- 녹화 중 새로고침 취소: 기존 페이지가 유지되므로 아무 상태도 제거하지 않는다.
- 분석 대기 중 새로고침: 활성 녹화 표식은 이미 제거되어야 하며 기존 ID로 분석 상태 폴링을 재개한다.
- 앱 내부 뒤로가기: 기존 커스텀 종료 확인 모달을 그대로 사용한다.
- 새로고침 경고 문구: 브라우저 보안 정책상 기본 `beforeunload` 문구를 사용한다.

## 검증

- 발표와 면접 각각 녹화 시작 성공 시 활성 표식이 생성되는지 검증한다.
- 새로고침 진입 시 스토어가 초기화되고 메인으로 `replace`되는지 검증한다.
- 일반 라우팅 진입과 녹화 시작 전 새로고침에서는 초기화되지 않는지 검증한다.
- 정상 완료 후 분석 화면 새로고침이 메인으로 이동하지 않는지 검증한다.
- 메인 안내가 한 번 표시된 뒤 소비되는지 검증한다.
