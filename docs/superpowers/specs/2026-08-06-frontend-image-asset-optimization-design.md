# 프런트 이미지 에셋 최적화 설계

## 목표

화면에 표시되는 크기보다 지나치게 큰 래스터 이미지를 전송·디코딩하는 비용을 줄이면서 고해상도 화면과 소셜 공유 이미지의 화질을 유지한다. 이미지의 화면 배치, 원형 크롭, 사용자 흐름과 공개 URL은 바꾸지 않는다.

## 선택한 방식

기존 파일 경로와 포맷을 유지한 채, 실제 최대 표시 크기의 약 3배를 기준으로 원본 픽셀 크기만 줄인다. 별도 `srcset`과 새 이미지 포맷을 추가하는 방식보다 코드·캐시·배포 계약 변경이 작고, 현재 에셋 수에서는 충분한 절감 효과가 있다.

- 면접관 사진: `1254×1254` JPG를 `384×384`로 축소한다. CSS 원형 영역은 `124×124`이므로 DPR 3에서도 원본 픽셀이 부족하지 않다.
- 면접 연습 일러스트: `1511×1041` PNG를 화면의 DPR 3 표시 크기를 넘는 약 `600×413`으로 축소한다.
- 발표 연습 일러스트: `708×800` PNG를 약 `456×515`로 축소한다.
- 홈 발표 이미지: 인페이지 표시와 OG 공유 이미지를 함께 담당하므로 1200px 폭을 유지하고 비율에 맞춰 축소한다.
- 로고와 슬라이드 이미지는 파일 크기가 작거나 큰 화면에서도 재사용되므로 이번 범위에서 유지한다.

## 미사용 파일 정리

`public/interviewers/*.png`는 JPG 전환 커밋 이후 코드에서 참조되지 않지만 Vite 배포 결과에는 복사된다. JPG 파일과 같은 면접관의 이전 원본이므로 제거하고, 안내 문서는 실제 JPG 계약과 `384×384` 권장 크기로 갱신한다.

`src/assets/images/home-interview-persona.png`는 `public/home-presenter.png`와 SHA-256이 동일하고 코드 참조가 없으므로 제거한다. 공개 `/home-presenter.png` URL은 OG/Twitter 메타데이터 계약을 위해 유지한다.

## 품질과 오류 처리

- 리사이즈는 원본 비율을 유지하고 고품질 다운샘플링을 사용한다.
- JPG는 얼굴 윤곽과 배경에 블록 노이즈가 생기지 않는 품질로 저장한다.
- PNG 투명도는 유지한다.
- 변환 전후 이미지 디코딩 여부, 픽셀 크기와 파일 크기를 자동 검사한다.
- 프로필 이미지는 원격 원본 URL 하나만 제공되는 구조라 프런트 리사이즈만으로 전송 비용을 줄일 수 없으므로 이번 범위에서 제외한다. 별도 썸네일 API 또는 이미지 CDN이 필요하다.

## 검증

1. 에셋 계약 테스트를 먼저 추가해 목표 픽셀 크기, 미사용 파일 부재와 공개 경로 유지를 검증한다.
2. 테스트가 기존 큰 이미지와 중복 파일 때문에 실패하는 것을 확인한다.
3. 이미지를 변환·정리한 뒤 계약 테스트와 전체 Vitest를 실행한다.
4. 프로덕션 빌드에서 이미지가 정상 포함되고 미사용 PNG가 제거됐는지 확인한다.
5. `/interview/style`, `/practice`, `/`를 브라우저에서 열어 원형 크롭, 선택 동작, 일러스트와 홈 포스터의 선명도 및 콘솔 오류를 확인한다.
