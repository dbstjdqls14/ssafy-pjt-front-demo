# 프런트 미디어·프로필·검증 결함 수정 설계

## 목표

발표 카메라 프레이밍, 슬라이드 축소, 발표·면접 리포트 영상 전환, 프로필 이미지 갱신, 닉네임 검증, 면접 TTS 중 비언어 측정 문제를 백엔드 변경 없이 해결한다.

## 완료 기준

- 발표 장치 확인과 녹화가 동일한 16:9 카메라 제약과 `contain` 프레이밍을 사용한다.
- 슬라이드 확대·축소 컨트롤은 60%까지 축소되고 초기화는 100%다.
- 리포트 ID가 바뀌면 이전 데이터·재생 상태·Object URL이 즉시 제거되고, 늦은 이전 응답이 새 리포트를 덮지 않는다.
- 면접 로컬 Blob은 생성한 면접 ID와 현재 리포트 ID가 일치할 때만 사용한다.
- 프로필 화면은 만료 가능한 presigned URL을 진입 시 갱신하고 이미지 변경을 URL 수명주기와 연결한다.
- 마이페이지 닉네임은 회원가입과 동일한 공통 검증기를 사용한다.
- 질문 TTS 동안 STT·업로드 레코더·얼굴 분석이 모두 멈추고, 해당 시간은 자세·시선 통계에서 제외된다.
- 면접 완료 요청은 `postureTiltPercent`와 `sampleCount`를 포함한 백엔드 지원 비언어 계약을 보낸다.

## 설계

### 카메라와 슬라이드

장치 확인과 발표 녹화에서 같은 `INTERVIEW_MEDIA_CONSTRAINTS`를 사용한다. CSS는 각 화면의 최종 우선순위 규칙에서 16:9 프레임과 `object-fit: contain`을 보장하며, 캡처 브리지는 입력 비율을 유지해 1280×720 캔버스 안에 그린다. 슬라이드 배율의 하한은 0.6, 기준값은 1로 유지한다.

### 리포트 영상 생명주기

리포트 ID를 단일 조회 키로 사용한다. ID 변경 시 화면 상태를 먼저 비우고 새 요청을 시작하며, 증가하는 요청 세대로 늦은 응답을 무시한다. 영상 DOM key는 리포트 ID·영상 ID·URL의 조합으로 만들고, 재생 컨트롤 상태도 미디어 key 변경 시 초기화한다. 면접 Object URL은 소유 ID를 확인한 뒤 생성하고 ID 전환 또는 언마운트 시 해제한다.

### 프로필 이미지와 닉네임

마이페이지 진입 시 `/users/me`를 호출해 30분 presigned URL을 갱신한다. 프로필 변경 응답은 Auth Store의 사용자 상태를 교체하며, 헤더 오류 복구는 갱신된 이미지 identity 단위로 다시 시도한다. 무작위 timestamp는 사용하지 않는다. 닉네임은 `usernameValidationMessage()` 결과를 그대로 사용한다.

### TTS와 비언어 측정

얼굴 분석기는 초기화와 수집 시작을 분리한다. 첫 질문을 포함한 모든 TTS 전에 수집을 일시정지하고, TTS가 끝난 뒤 답변을 수집할 수 있는 상태에서만 재개한다. pause 구간은 활성 경과 시간에서 제외하고 재개 직후 첫 샘플은 시선 이탈 기준점으로만 사용한다. 세션 요약은 활성 샘플에서 전체 자세 기울기 비율과 샘플 수를 계산한다.

## 오류 처리와 범위 제한

- 미디어 조회 실패 시 이전 리포트 영상을 유지하지 않고 빈 상태와 오류를 보여준다.
- 전역 RouterView를 `fullPath`로 재마운트하지 않는다.
- presigned URL에 `Date.now()`를 붙이지 않는다.
- 백엔드의 닉네임 API 우회 방지와 사용하지 않는 S3 프로필 이미지 삭제는 이번 프런트 범위 밖이다.
- 기존 사용자 미커밋 변경과 관련 없는 파일은 수정하지 않는다.

## 검증

각 결함을 재현하는 Vitest를 먼저 실패시키고 최소 구현으로 통과시킨다. 관련 테스트 전체, ESLint, 프로덕션 빌드를 실행한다. 카메라 실기기 검증이 불가능하면 자동 검증 결과와 남은 수동 검증 항목을 명시한다.
