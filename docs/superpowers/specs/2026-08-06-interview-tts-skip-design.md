# 면접 질문 TTS 건너뛰기 설계

## 목표

면접 녹화 중 질문을 읽어주는 TTS가 재생될 때 사용자가 `바로 답변하기` 버튼으로 음성을 즉시 건너뛰고 답변 상태로 전환할 수 있게 한다. 전환 과정에서 카메라·마이크 스트림, 영상·오디오 레코더, PCM 수집기, STT와 MediaPipe 인스턴스를 종료하거나 새로 만들지 않는다.

## 사용자 동작

- `바로 답변하기` 버튼은 면접이 시작됐고 현재 질문 TTS가 재생 중일 때만 표시한다.
- 버튼은 기존 `질문을 읽는 중이에요 — 끝나면 답변을 시작하세요` 안내 영역에 함께 배치한다.
- 사용자가 버튼을 누르면 별도 카운트다운 없이 TTS를 즉시 취소한다.
- 일시정지돼 있던 답변 캡처 자원을 재개한 뒤 현재 질문의 답변 타이머·자막·분석을 시작한다.
- 질문을 변경하거나 현재 질문을 답변 완료로 표시하지 않는다.
- 이미 TTS가 끝났거나 스킵 전환이 처리 중이면 버튼 동작을 중복 실행하지 않는다.

## 상태 전환

전용 비동기 함수 `skipQuestionTts()`가 다음 순서로 처리한다.

1. 현재 면접·TTS 상태와 중복 처리 잠금을 확인한다.
2. TTS 실행 번호인 `ttsRunId`를 증가시켜 기존 utterance의 늦은 `onend`·`onerror` 콜백을 무효화한다.
3. `window.speechSynthesis.cancel()`로 현재 질문 음성을 취소한다.
4. TTS 재생 상태를 해제한다.
5. 기존 `resumeAnswerCapture()`를 기다려 영상·오디오 업로드 레코더, PCM 수집, MediaPipe와 STT를 같은 인스턴스로 재개한다.
6. 재개가 끝날 때까지 TTS 스킵 버튼과 다음 질문·종료 버튼의 중복 동작을 잠근다.

TTS의 정상 종료와 스킵은 동일한 답변 캡처 재개 경로를 사용한다. 카메라·마이크 트랙을 정지하거나 `useFaceAnalysis()`를 다시 생성하지 않으며, `startFaceAnalysis()` 대신 기존 `resumeFaceAnalysis(videoEl)`을 호출한다.

## 오류 및 경합 처리

- TTS를 취소할 때 브라우저가 기존 utterance의 `onend` 또는 `onerror`를 뒤늦게 호출해도 증가한 `ttsRunId`가 콜백을 무효화한다.
- 사용자가 버튼을 빠르게 여러 번 눌러도 전용 처리 상태와 기존 주요 동작 interlock으로 재개는 한 번만 실행한다.
- 재개 도중 카메라나 마이크 권한이 사라지면 기존 `deviceBlocked` 상태와 권한 복구 모달을 사용한다.
- 장치가 차단된 동안 질문 타이머와 답변 분석은 진행하지 않는다.
- TTS 미지원 브라우저에서는 기존처럼 질문을 읽지 않고 곧바로 답변 캡처를 시작하므로 스킵 버튼도 표시하지 않는다.

## 데이터와 리포트 영향

- 질문 ID, 답변 텍스트, 질문별 PCM 시작·종료 시각 계약은 변경하지 않는다.
- TTS 동안 PCM·STT·MediaPipe와 업로드 레코더가 일시정지되는 기존 규칙을 유지한다.
- 스킵한 TTS의 미재생 잔여 시간은 답변 구간에 포함되지 않는다.
- API 요청, Pinia 저장 구조와 백엔드 수정은 필요하지 않다.

## UI

- 기존 TTS 안내 문구와 동일한 카메라 하단 안내 영역 안에 `바로 답변하기` 버튼을 배치한다.
- 버튼은 안내 문구와 시각적으로 구분되는 밝은 보조 버튼으로 표시하고 키보드 포커스 스타일을 제공한다.
- 화면이 좁으면 안내 문구와 버튼이 줄바꿈될 수 있게 하여 카메라 영역 밖으로 넘치지 않게 한다.
- 처리 중에는 버튼을 비활성화하고 중복 입력을 받지 않는다.

## 검증

`InterviewRecordInterlock.test.js`에서 다음을 검증한다.

1. TTS 재생 중에만 `바로 답변하기` 버튼이 표시된다.
2. 클릭 시 `speechSynthesis.cancel()`이 호출되고 질문과 질문 인덱스는 유지된다.
3. 영상·오디오 레코더는 새로 시작되거나 종료되지 않고 각각 한 번 재개된다.
4. PCM 수집, STT와 MediaPipe가 재개되고 답변 타이머가 진행된다.
5. 취소 후 늦은 `onend`가 도착해도 재개가 중복 실행되지 않는다.
6. 빠른 중복 클릭에서도 재개는 한 번만 실행된다.
7. 기존 정상 TTS 종료, 다음 질문, 면접 종료와 장치 복구 테스트가 계속 통과한다.

구현 후 전체 Vitest, 프로덕션 빌드와 실제 브라우저의 첫 질문·다음 질문 TTS 스킵 흐름을 확인한다.
