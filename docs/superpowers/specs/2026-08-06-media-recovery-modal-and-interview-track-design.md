# 권한 복구 모달 통일 및 면접 트랙 생명주기 설계

## 목표

발표와 면접 녹화 화면의 카메라·마이크 권한 복구 UI와 동작을 하나로 통일한다. 면접 시작 카운트다운 전후에 동일한 미디어 트랙을 재연결하면서 트랙이 종료되어 검은 화면이나 무음 녹화가 발생하는 문제도 함께 해결한다.

## 확인된 현재 문제

### 면접 카운트다운 이후 검은 화면

면접 시작 버튼을 누르면 `connectCaptureSources()`가 카메라와 마이크 트랙을 캡처 브리지에 연결한 뒤 5초 카운트다운을 시작한다. 카운트다운이 끝난 `actuallyStart()`에서도 같은 `connectCaptureSources()`가 실행된다.

현재 캡처 브리지의 `connectVideoTrack()`과 `connectAudioTrack()`은 새 소스를 연결하기 전에 기존 소스를 `stop()`한다. 기존 소스와 새 소스가 같은 객체인 경우에도 동일하게 종료하므로, 두 번째 연결 직후 트랙의 `readyState`가 `ended`가 된다. UI 상태는 다시 켜짐으로 설정돼 있어 브라우저에 따라 마지막 프레임, 검은 화면 또는 무음 녹화로 나타날 수 있다.

현재 테스트용 트랙의 `stop()`은 `readyState`를 `ended`로 바꾸지 않으며, 면접 화면 테스트의 캡처 브리지도 단순 mock이다. 따라서 기존 테스트는 이 문제를 검출하지 못한다.

### 권한 복구 모달 불일치

발표와 면접은 서로 다른 마크업과 CSS로 권한 복구 모달을 렌더링한다. 종료 버튼, 버튼 라벨, 단계별·장치별 안내 문구, 복구 후 자동 재개 여부도 서로 다르다.

## 사용자 노출 규칙

발표와 면접은 동일한 공통 모달을 사용한다.

- 제목: `카메라와 마이크 권한이 필요합니다.`
- 본문: `주소창 왼쪽의 사이트 설정에서 권한을 허용한 뒤 다시 요청해 주세요.`
- 버튼: `확인`
- 권한 확인 중 버튼: `확인 중…`
- 발표의 `발표 종료하기` 버튼을 제거한다.
- 면접의 `면접 종료` 버튼을 제거한다.
- `카메라 연결이 끊겨 면접을 일시적으로 멈췄습니다.`를 포함한 장치별·단계별 문장을 제거한다.
- 브라우저 원문 오류인 `Permission denied` 등은 노출하지 않는다.

일반적인 뒤로가기·종료 확인 모달과 녹화 완료 버튼은 이번 변경 대상이 아니다. 권한 상실 시에 표시되는 권한 복구 모달만 통일한다.

## 구조

### 공통 권한 모달 컴포넌트

`src/components/common/RequiredMediaPermissionModal.vue`를 만든다.

각 녹화 화면은 `deviceBlocked`일 때만 컴포넌트를 렌더링한다. 컴포넌트는 다음 인터페이스만 가진다.

- `busy: boolean`: 권한 확인 진행 여부
- `confirm` 이벤트: 사용자가 확인 버튼을 눌렀을 때 발생

제목과 본문은 제품 규칙으로 고정한다. 화면별 종료 동작이나 라우터 동작은 포함하지 않는다. 이를 통해 발표와 면접이 문구·마크업·스타일을 공유하면서도 실제 미디어 복구는 각 녹화 화면이 담당한다.

### 캡처 브리지의 소스 트랙 소유권

카메라·마이크 원본 트랙은 `useMediaDevices`가 소유한다. 캡처 브리지는 원본 트랙을 소비하지만 교체·연결 과정에서 직접 종료하지 않는다.

- 같은 트랙이 이미 연결돼 있고 `live` 상태라면 연결 함수는 즉시 반환한다.
- 다른 트랙으로 교체할 때 브리지는 기존 연결만 해제하고 원본 트랙에 `stop()`을 호출하지 않는다.
- 원본 트랙 종료는 `releaseVideo()`, `releaseAudio()`, `stopStream()` 등 `useMediaDevices` 경로에서 수행한다.
- 브리지의 고정 출력 트랙과 오디오 컨텍스트는 `dispose()`에서 계속 정리한다.

이 경계는 같은 트랙 재연결 문제를 막고 소스 트랙의 이중 종료를 없앤다.

## 권한 복구 데이터 흐름

### 진행 중 권한 상실

1. 기존 녹화·음성 인식·PCM 수집·시선 및 자세 분석을 일시정지한다.
2. 공통 권한 모달을 표시한다.
3. 사용자가 `확인`을 누르면 카메라와 마이크를 모두 다시 요청한다.
4. 두 트랙이 모두 `live`인지 확인한다.
5. 성공하면 캡처 브리지에 새 트랙을 연결하고 모달을 닫는다.
6. 권한 상실 직전에 자동으로 진행 중이던 경우에만 녹화와 분석을 자동 재개한다.

발표도 면접과 동일하게 성공 시 자동 재개한다. 사용자가 권한 상실 전에 이미 수동 일시정지한 상태였다면 자동 재개하지 않는다.

### 시작 전 권한 실패

1. 카운트다운 또는 시작 시도를 취소한다.
2. 공통 권한 모달을 표시한다.
3. 사용자가 `확인`을 누르면 카메라와 마이크를 다시 요청한다.
4. 성공하면 모달을 닫고 원래 시작 화면으로 돌아간다.
5. 사용자가 다시 시작 버튼을 눌러야 카운트다운이 시작된다. 자동으로 녹화를 시작하지 않는다.

### 재요청 실패

- 모달을 닫지 않는다.
- 버튼을 `확인 중…`에서 `확인`으로 되돌린다.
- 추가 오류 문장은 표시하지 않는다.
- 다음 확인 시도에서 다시 `getUserMedia()`를 호출한다.

## 오류 및 경쟁 조건 처리

- 확인 버튼 연속 클릭은 `checking` 상태로 차단한다.
- 장치 요청 성공 후에도 카메라와 마이크 트랙이 모두 `live`인지 확인한다.
- 권한 확인 중 컴포넌트가 해제되거나 녹화가 종료되면 후속 자동 재개를 실행하지 않는다.
- 동일 트랙 연결은 멱등 동작이어야 한다.
- 서로 다른 새 트랙 연결은 이전 연결을 해제하되 이전 원본 트랙을 브리지가 종료하지 않는다.

## 테스트 전략

### 캡처 브리지

- 동일 카메라 트랙을 두 번 연결해도 `stop()`이 호출되지 않고 `readyState`가 `live`로 유지되는지 검증한다.
- 동일 마이크 트랙도 같은 규칙을 따르는지 검증한다.
- 다른 트랙으로 교체할 때 출력 스트림 identity는 유지되고 브리지가 이전 원본 트랙을 종료하지 않는지 검증한다.
- `dispose()`가 브리지 출력 트랙과 오디오 컨텍스트를 정리하는지 유지한다.

### 면접 녹화

- 시작 버튼 클릭과 카운트다운 종료 사이에 동일 카메라·마이크 트랙이 종료되지 않는지 검증한다.
- 5초 후 녹화가 살아 있는 캡처 브리지 출력으로 시작하는지 검증한다.
- 권한 복구 성공 시 직전 진행 상태로 자동 재개하는지 검증한다.
- 시작 전 실패 복구 시 모달만 닫히고 면접은 자동 시작되지 않는지 검증한다.

### 발표 녹화

- 공통 모달 문구와 단일 확인 버튼을 검증한다.
- 권한 복구 성공 시 자동 재개하는지 검증한다.
- 시작 전 실패 복구 시 자동 녹화 시작 없이 시작 화면으로 복귀하는지 검증한다.
- 실패 시 모달 유지와 브라우저 원문 오류 비노출을 검증한다.

### 렌더링

- 발표와 면접의 모달이 동일한 크기, 간격, 배경, 버튼 스타일을 사용하는지 확인한다.
- 데스크톱과 좁은 화면에서 문구와 버튼이 잘리지 않는지 확인한다.

## 범위 제외

- 브라우저 주소창에서 차단된 권한을 웹페이지가 직접 허용으로 변경하는 기능
- 일반 종료·뒤로가기 확인 모달 변경
- 녹화 완료 API 또는 백엔드 변경
- 장치 확인 화면의 권한 UI 변경
- 권한 복구와 무관한 면접 답변·TTS 동작 변경
