# 녹화 권한 시작 구간 방어 설계

## 목표

브라우저 주소창에서 카메라 또는 마이크 권한을 차단했을 때 면접이 시작 직후 종료된 것처럼 보이는 문제를 해결한다. 발표 화면의 권한 복구 안내도 같은 원칙으로 정리하고, 내 기록의 발표 연습 날짜 마지막 마침표를 제거한다.

## 확인된 원인

- 면접 녹화는 5초 카운트다운 뒤 장치를 확보하기 전에 `started`와 녹화 Store를 먼저 시작한다. 장치 요청이 `NotAllowedError`로 실패하면 이미 시작한 상태를 되돌리면서 즉시 종료된 것처럼 보인다.
- 면접의 장치 손실 처리기는 `started` 상태에서만 동작해 5초 카운트다운 도중의 권한 해제를 처리하지 않는다.
- 발표 권한 재요청 버튼은 `getUserMedia()`를 호출하지만, 주소창에서 영구 차단된 권한은 웹페이지가 직접 허용으로 바꾸거나 권한 팝업을 강제로 열 수 없다. 재요청 실패 시 브라우저 원문 `Permission denied`가 노출될 수 있다.
- 발표 리포트 날짜는 한국어 `Intl.DateTimeFormat` 결과의 마지막 마침표를 그대로 표시한다.

## 설계

### 면접 시작 전 장치 방어

면접 시작 버튼을 누르면 사용자 클릭 흐름 안에서 카메라와 마이크를 먼저 요청한다. 두 실제 트랙이 모두 살아 있을 때만 5초 카운트다운을 시작한다.

카운트다운 중 트랙이 종료되면 카운트다운을 취소하고 시작 단계 권한 모달을 표시한다. 카운트다운이 끝나는 순간에도 트랙을 다시 확인하고 capture bridge 연결까지 완료한 뒤에만 녹화 Store와 면접 상태를 시작한다. 따라서 시작 직전의 권한 변경과 트랙 종료 경합을 모두 막는다.

녹화가 시작된 뒤에는 기존 장치 손실 방어를 유지한다. 장치 종료 시 녹화·음성 인식·TTS·비언어 분석을 일시정지하고 복구 전까지 주요 동작을 차단한다.

### 권한 복구 UX

면접과 발표의 권한 버튼은 실제 `getUserMedia()` 재요청을 수행한다. 권한이 아직 요청 전 상태면 브라우저 팝업이 열릴 수 있다. 이미 주소창에서 차단한 경우에는 팝업을 강제로 열 수 없으므로, 주소창 왼쪽 사이트 설정에서 카메라와 마이크를 허용한 뒤 다시 누르라는 안내를 표시한다.

`NotAllowedError`, `PermissionDeniedError`, `SecurityError`의 브라우저 원문은 화면에 그대로 출력하지 않는다. 시작 단계와 녹화 중단 단계의 안내 문구는 구분하되 동일한 복구 버튼을 사용한다.

### 날짜 표시

발표 리포트 연습 날짜는 기존 지역 시간 기준을 유지하면서 표시 문자열 끝의 마침표만 제거해 `YYYY.MM.DD` 형태로 통일한다.

## 완료 기준

- 시작 시 권한이 차단되면 면접 녹화 상태가 시작되지 않고 권한 모달이 표시된다.
- 5초 카운트다운 중 권한을 차단하면 카운트다운이 취소되고 녹화가 시작되지 않는다.
- 권한 복구 성공 후 다시 시작할 수 있다.
- 녹화 중 장치 손실 방어는 기존대로 동작한다.
- 면접과 발표에서 브라우저 원문 `Permission denied`가 노출되지 않는다.
- 발표 연습 날짜는 마지막 마침표 없이 표시된다.

## 비범위

- 브라우저 사이트 권한을 웹페이지가 직접 변경하는 기능
- 운영체제 개인 정보 보호 설정을 여는 기능
- 백엔드 API 변경
