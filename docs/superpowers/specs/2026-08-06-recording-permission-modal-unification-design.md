# 발표·면접 녹화 권한 모달 통일 설계

## 목표

발표와 면접 녹화 중 카메라 또는 마이크 권한을 잃었을 때 동일한 모달을 표시한다. 사용자는 종료 선택 없이 권한을 복구한 뒤 `확인` 버튼으로 재검사하며, 카메라와 마이크가 모두 복구된 경우에만 모달을 닫고 중단 전 상태로 돌아간다.

## 사용자 노출 문구

- 제목: `카메라와 마이크 권한이 필요합니다.`
- 본문: `주소창 왼쪽의 사이트 설정에서 권한을 허용한 뒤 다시 요청해 주세요.`
- 기본 버튼: `확인`
- 권한 확인 중 버튼: `확인 중…`

장치 종류나 발생 단계에 따라 제목과 본문을 바꾸지 않는다. 다음 문구와 같은 진행 중단 설명은 표시하지 않는다.

- `카메라 연결이 끊겨 면접을 일시적으로 멈췄습니다.`
- `마이크 연결이 끊겨 발표를 일시적으로 멈췄습니다.`

브라우저에서 받은 `Permission denied` 등 원문 오류도 모달에 표시하지 않는다.

## UI 구조

면접 권한 모달을 시각 기준으로 삼는다. 발표와 면접은 새 공통 컴포넌트 `RequiredMediaPermissionModal.vue`를 사용한다.

공통 컴포넌트의 책임은 다음으로 제한한다.

- 고정된 제목과 본문 렌더링
- `확인` 단일 버튼 렌더링
- 요청 중 `확인 중…` 표시와 버튼 비활성화
- `confirm` 이벤트 전달

권한 요청이나 녹화 재개는 공통 컴포넌트가 직접 수행하지 않는다. 발표·면접 화면이 기존 미디어 장치와 녹화 생명주기를 계속 소유한다.

## 권한 재확인 흐름

1. 카메라 또는 마이크 권한 상실을 감지한다.
2. 진행 중이던 녹화, 음성 인식과 실시간 분석을 안전하게 일시정지한다.
3. 공통 권한 모달을 표시한다.
4. 사용자가 `확인`을 누르면 버튼을 `확인 중…`으로 바꾸고 카메라와 마이크를 모두 다시 요청한다.
5. 새 비디오·오디오 트랙이 모두 활성 상태인지 확인하고 녹화 소스에 다시 연결한다.
6. 둘 중 하나라도 복구되지 않았다면 모달을 유지하고 버튼을 `확인`으로 되돌린다.
7. 둘 다 복구됐다면 모달을 닫고 중단 전 진행 상태로 자동 복귀한다.

## 상태별 복귀 동작

### 진행 중 권한 상실

- 면접: 권한 상실 직전에 면접이 진행 중이었다면 녹화, 음성 인식, PCM 수집과 자세·시선 분석을 자동 재개한다.
- 발표: 권한 상실 직전에 발표가 진행 중이었다면 녹화, 음성 인식, PCM 수집과 자세·시선 분석을 자동 재개한다.
- 사용자가 권한을 복구한 뒤 별도로 재개 버튼을 누를 필요가 없다.

### 시작 전 또는 시작 처리 중 권한 실패

- 카메라와 마이크 복구 성공 시 모달만 닫는다.
- 발표나 면접을 자동 시작하지 않는다.
- 사용자가 원래 화면의 `발표 시작하기` 또는 `면접 시작` 버튼으로 다시 시작한다.

### 재확인 실패

- 공통 모달을 계속 표시한다.
- `확인 중…`을 `확인`으로 되돌려 다시 시도할 수 있게 한다.
- 종료나 화면 이동을 자동 수행하지 않는다.
- 원문 오류 또는 추가 오류 문단을 노출하지 않는다.

## 제거 범위

권한 모달에서 다음 요소를 제거한다.

- 발표의 `발표 종료하기` 버튼
- 면접의 `면접 종료` 버튼
- 발표의 `권한 허용하기` 문구
- 면접의 `권한 다시 요청` 문구
- 발표의 권한 오류 상세 문단

일반 뒤로가기·나가기 확인 모달과 정상적인 발표·면접 종료 버튼은 이번 변경 대상이 아니다.

## 테스트 전략

공통 컴포넌트 테스트에서 고정 문구, 단일 버튼, 요청 중 상태와 `confirm` 이벤트를 검증한다.

발표와 면접 화면 테스트에서는 다음을 검증한다.

- 시작 단계 권한 실패 시 공통 모달이 표시된다.
- 진행 중 카메라 또는 마이크 권한 상실 시 공통 모달이 표시된다.
- 모달에 종료 버튼, 장치별 중단 문구와 브라우저 원문 오류가 없다.
- 권한 재확인 실패 시 모달이 유지되고 재시도할 수 있다.
- 권한 재확인 성공 시 모달이 닫힌다.
- 진행 중이었다면 녹화와 분석이 자동 재개된다.
- 시작 전이었다면 자동으로 녹화를 시작하지 않는다.

전체 프런트 테스트와 프로덕션 빌드를 실행하고, 로컬 화면에서 발표·면접 모달의 레이아웃이 동일한지 확인한다. 실제 브라우저 권한 변경은 주소창의 사이트 설정에서 사용자가 수행해야 하며 웹페이지가 권한 상태를 강제로 변경하지 않는다.
