# 종료된 발표 세션 녹화 화면 재진입 방어 설계

## 문제

발표 분석이 끝나면 분석 화면은 `/presentation/report`로 교체되지만, 그보다 앞선 `/presentation/record` 항목은 브라우저 히스토리에 남는다. 사용자가 리포트 요약 화면에서 브라우저 뒤로가기를 누르면 이미 종료된 발표의 녹화 화면이 다시 마운트되고 카메라·마이크 초기화를 시도한다.

## 목표

- 완료된 발표 세션으로 녹화 화면에 다시 들어가지 못하게 한다.
- 재진입이 감지되면 `종료된 세션입니다.`를 한 번 안내하고 홈(`/`)으로 이동한다.
- 완료된 리포트와 발표 식별 정보는 보존한다.
- 진행 중인 정상 발표 세션의 녹화 진입과 새로고침 복구 동작은 변경하지 않는다.

## 선택한 구조

### 녹화 화면 진입 방어

`PresentationRecordView`가 마운트될 때 `presentation.sessionStatus === 'completed'`를 장치 초기화보다 먼저 확인한다. 완료 상태라면 다음 순서로 처리한다.

1. 활성 녹화 표시를 제거한다.
2. `recordingStore`의 일시적인 녹화 상태를 초기화한다.
3. 홈에서 소비할 일회성 완료 세션 안내를 저장한다.
4. `router.replace('/')`로 현재 녹화 히스토리 항목을 홈으로 교체한다.
5. 슬라이드 로딩과 카메라·마이크 초기화를 실행하지 않는다.

`presentationStore`는 초기화하지 않는다. 완료된 리포트 데이터와 발표 ID를 유지해 브라우저 앞으로가기나 상세 리포트 이동 시 불필요한 데이터 유실을 막는다.

### 일회성 홈 안내

기존 녹화 복구 안내 저장 구조에 안내 사유를 추가한다.

- 기존 새로고침 복구: 현재 문구 유지
- 완료 세션 재진입: `종료된 세션입니다.` 표시

홈이 안내를 한 번 소비하면 기존처럼 저장소에서 제거한다. 따라서 이후 홈 재방문에서는 같은 안내가 반복되지 않는다.

## 제외 범위

- 브라우저 전체 히스토리를 삭제하거나 뒤로가기 버튼 자체를 비활성화하지 않는다.
- 전역 라우터 가드에 발표 Store 의존성을 추가하지 않는다.
- 리포트 화면의 정상적인 상세 리포트·홈 이동은 변경하지 않는다.
- 완료된 발표 Store와 리포트 데이터를 초기화하지 않는다.

## 오류 및 경계 조건

- 완료 세션 안내 저장에 실패해도 홈 이동은 수행한다.
- 이미 활성 녹화 표시가 없어도 동일하게 안전하게 처리한다.
- `draft`, `ready`, `recording`, `review` 등 완료 전 상태는 기존 녹화 진입 흐름을 따른다.
- 새로고침으로 진행 중인 녹화를 복구하는 기존 조건은 완료 세션 판별과 독립적으로 유지한다.

## 검증

- 완료 세션 상태에서 녹화 경로 진입 시 홈으로 교체되는지 검증한다.
- 완료 세션에서는 슬라이드 로딩과 장치 확인이 호출되지 않는지 검증한다.
- 홈에 `종료된 세션입니다.`가 한 번만 표시되는지 검증한다.
- 기존 새로고침 복구 안내 문구가 유지되는지 검증한다.
- 진행 중인 정상 세션이 기존처럼 녹화 화면에 남는지 검증한다.
- 관련 집중 테스트, 전체 Vitest, 프로덕션 빌드와 실제 브라우저 뒤로가기 흐름을 확인한다.
