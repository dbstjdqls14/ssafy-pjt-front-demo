# 사용자 인식 글자 수 및 입력 정책 설계

## 목표

글자 수가 표시되는 입력란은 JavaScript의 UTF-16 코드 단위가 아니라 사용자가 화면에서 한 글자로 인식하는 grapheme cluster 단위로 계산한다. 입력, 붙여넣기, 카운터, 제출 검증이 같은 기준을 사용하며, 허용되지 않는 문자는 자동 삭제하지 않고 사용자가 직접 수정하도록 한다.

이번 변경은 프런트 입력 경험을 통일하는 작업이다. 이메일, 비밀번호, 검색, 파일 및 선택 입력은 기존 동작을 유지한다.

## 공통 글자 수 계산

- `Intl.Segmenter('ko', { granularity: 'grapheme' })`를 기본 계산기로 사용한다.
- 지원되지 않는 환경에서는 코드 포인트 단위 분리를 대체 경로로 사용한다.
- 한글, 영문, 숫자와 일반 기호는 각각 화면에 보이는 한 글자로 센다.
- 단일 이모지, 피부색 결합 이모지, 국기, ZWJ 가족 이모지는 각각 한 글자로 센다.
- CRLF는 하나의 LF 줄바꿈으로 검사하고, NFC 정규화 후 검증한다.

## 입력 정책

### 닉네임

- 한글, ASCII 영문, ASCII 숫자, 밑줄(`_`)만 허용한다.
- 공백, 이모지 및 그 밖의 문자는 오류로 표시한다.

### 짧은 이름과 제목

- 한글, ASCII 영문, ASCII 숫자, 일반 공백(U+0020), `@`만 허용한다.
- 발표·면접 연습 이름, 폴더 이름, 자료 제목에 적용한다.

### 설명, 질문 및 슬라이드 핵심 내용

- 언어, 문자 체계, 문장부호, 기호, 공백, 탭을 제한하지 않는다.
- 여러 줄 입력란은 줄바꿈을 허용한다. 단일 줄 입력란은 브라우저의 기본 단일 줄 동작을 따른다.
- 문자 종류에 대해서는 실제 이모지 표현만 거부한다.
- `😊`, `❤️`, ZWJ 가족 이모지, 국기, 키캡 이모지처럼 이모지로 표시되는 시퀀스를 거부한다.
- `©`, `♥`, `℃`, `→`, `···`, 곡선 따옴표처럼 일반 문자나 텍스트 기호로 표시되는 값은 허용한다.
- 프런트가 탭, 제어 문자 또는 보이지 않는 서식 문자를 별도 오류로 만들지 않는다.

이 정책은 PPT 또는 AI가 생성한 문장도 동일하게 처리한다. 따라서 `‘오늘의 건수’`, `·········` 같은 분석 결과는 오류가 아니다.

## 최대 길이

- 정책 대상 입력란에 네이티브 `maxlength`를 사용하지 않는다. 네이티브 제한은 UTF-16 코드 단위라 이모지와 결합 문자를 사용자 인식 글자 수와 다르게 센다.
- 각 필드의 기존 최대 길이를 grapheme 단위로 강제한다.
- 직접 입력은 최대 길이에 도달하면 추가 글자를 반영하지 않는다.
- 붙여넣기와 드래그 입력은 들어갈 수 있는 grapheme까지만 반영한다.
- 결합 이모지나 결합 문자를 중간에서 잘라 깨진 문자열을 만들지 않는다.
- 한글 IME 조합 중에는 값을 자르지 않고 `compositionend` 이후 최대 길이를 적용한다.
- 서버에서 이미 최대 길이를 초과한 값이 내려오면 불러오는 즉시 자르지 않는다. 전체 값을 보여주고 길이 오류와 제출 차단을 적용해 기존 데이터가 조용히 손실되지 않게 한다.

## 잘못된 문자 처리

- 최대 길이 이내에 입력된 허용되지 않는 문자는 Vue 모델과 입력란에 그대로 남긴다.
- 입력란 아래에 정책 오류를 즉시 표시한다.
- 사용자가 직접 수정해 정상 값이 되기 전까지 저장, 다음 단계 이동 및 API 요청을 차단한다.
- 최대 길이를 넘는 부분만 입력 제한 규칙에 따라 반영하지 않는다.

예를 들어 닉네임 입력란에 이모지가 포함된 30자를 붙여넣으면 앞의 20 grapheme만 남고 이모지는 그대로 보인다. 화면은 이모지 오류를 표시하고 사용자가 직접 제거할 때까지 저장하지 않는다.

## 사용자 안내

- 닉네임: `닉네임은 한글, 영문, 숫자, 밑줄만 입력할 수 있어요.`
- 짧은 이름과 제목: `한글, 영문, 숫자, 공백, @만 입력할 수 있어요.`
- 설명·질문·슬라이드 핵심 내용: `이모지는 입력할 수 없어요.`
- 기존 서버 값의 길이 초과: `최대 N자까지 입력할 수 있어요.`

카운터는 현재 모델 값의 전체 grapheme 수를 표시한다. 새 입력은 최대 길이를 넘을 수 없지만, 기존 서버 값이 초과된 경우에는 실제 초과 수치를 보여준다.

## 구현 구조

공통 순수 함수 유틸리티가 다음 책임을 가진다.

- grapheme 분리와 개수 계산
- 최대 grapheme까지만 안전하게 자르기
- 실제 이모지 표현 검출
- 필드 정책과 최대 길이 검증

각 Vue 화면은 공통 유틸리티를 사용해 모델 값, 카운터, IME 조합 상태와 오류 문구를 관리한다. 닉네임, 발표·면접 설명, 폴더와 자료 입력, 슬라이드 핵심 내용 및 면접 질문이 같은 경계를 사용한다.

Pinia Store는 제출 직전에 같은 정책으로 다시 검증한다. 화면을 우회하거나 서버 값이 모델에 직접 들어온 경우에도 잘못된 payload를 API로 보내지 않는다.

## 검증 계획

### 공통 유틸리티

- 한글, 영문, 숫자, 결합 문자와 여러 종류의 이모지 grapheme 계산
- 최대 길이에서 일반 입력과 붙여넣기 값 제한
- 결합 문자를 중간에서 자르지 않는지 검증
- 이모지 표현 거부와 일반 텍스트 기호 허용
- 곡선 따옴표, 가운데점, 한자, 일본어, 탭 및 줄바꿈 허용

### 화면

- 최대 길이에 도달한 뒤 추가 입력이 반영되지 않음
- 최대 길이를 넘긴 붙여넣기는 들어갈 수 있는 글자까지만 반영됨
- 한글 IME 조합이 중간에 잘리지 않음
- 이모지는 값에 남아 오류가 표시되고 제출이 차단됨
- 이모지를 직접 제거하면 오류가 사라짐
- 기존 서버 초과 값은 자동으로 잘리지 않고 제출이 차단됨

### 회귀 검증

- 전체 Vitest 실행
- Vite 프로덕션 빌드
- 브라우저 수동 검증은 사용자가 별도로 요청할 때만 진행

## 완료 기준

- 글자 수 표시, 직접 입력, 붙여넣기, 화면 검증과 Store 제출 검증이 모두 grapheme 단위를 사용한다.
- 새 입력은 필드 최대 길이를 넘지 않는다.
- 설명·질문·슬라이드 핵심 내용은 일반 텍스트를 제한하지 않고 실제 이모지만 거부한다.
- 허용되지 않는 문자는 자동 삭제되지 않으며, 사용자 수정 전까지 제출되지 않는다.
- 기존 서버 초과 값은 자동으로 손실되지 않는다.
- 전체 테스트와 프로덕션 빌드가 통과한다.
