# 발표 complete 안전 경계 및 질의응답 새로고침 처리 설계

## 목표

발표 녹화 파일이 서버에 안전하게 접수되기 전과 서버 분석 작업이 시작된 이후를 명확히 구분한다. 서버 접수 전에는 페이지 이탈과 새로고침으로 녹화 데이터가 유실될 수 있음을 안내하고 이탈을 방어한다. 서버 상태가 `PENDING` 이상으로 확인된 뒤에는 동일한 안내 카드에서 백그라운드 분석 안내로 문구를 전환하고 자유로운 이탈을 허용한다.

질문 생성 또는 질의응답 도중 강제 새로고침으로 메모리의 녹화 Blob이 유실되면 손상된 세션을 이어가지 않고 세션을 폐기한 뒤 홈으로 이동한다.

## 범위

- 발표 분석 화면의 complete 업로드 상태와 리포트 상태 폴링
- 분석 화면의 안내 카드와 라우트·브라우저 이탈 방어
- 발표 질문 생성 및 질의응답 화면의 새로고침 감지와 세션 폐기
- 관련 단위·컴포넌트 테스트와 프로덕션 빌드

다음 항목은 범위에서 제외한다.

- 백엔드 API 및 상태값 변경
- 서비스 워커나 브라우저 백그라운드 업로드
- 이미 생성된 리포트 내용 변경
- 실제 브라우저를 이용한 수동·자동 UI 테스트

## 서버 상태 계약

`POST /api/v1/presentations/{presentationId}/complete`로 녹화 파일과 발표 데이터를 전송한 뒤 `GET /api/v1/presentations/{presentationId}/status`를 폴링한다.

처리 상태는 다음과 같다.

- `PENDING`: complete 요청이 서버에 접수되고 분석 작업이 대기 중
- `STT_ANALYZING`: 음성 인식 분석 중
- `LLM_ANALYZING`: 내용 및 피드백 생성 중
- `COMPLETED`: 리포트 생성 완료
- `FAILED`: 처리 실패

`PENDING`, `STT_ANALYZING`, `LLM_ANALYZING`, `COMPLETED` 중 하나를 처음 확인한 시점을 서버 접수 완료 경계로 사용한다. 폴링 간격과 최대 시도 횟수는 기존 분석 화면 설정을 유지한다.

## 상태 모델

분석 화면은 다음 상태를 구분한다.

1. `uploading`: `/complete` 요청을 보내는 중이거나 첫 유효 서버 상태를 아직 확인하지 못한 상태
2. `accepted`: `PENDING`, `STT_ANALYZING`, `LLM_ANALYZING` 중 하나를 확인한 상태
3. `completed`: `COMPLETED`를 확인하고 리포트를 조회한 상태
4. `failed`: complete 요청, 상태 조회 또는 서버 분석이 실패한 상태

화면에 내부 상태명이나 “복구 불가능한 발표 데이터” 같은 개발 용어를 노출하지 않는다.

## 안내 카드

업로드 안내와 백그라운드 분석 안내는 동일한 카드 DOM과 동일한 스타일을 사용한다. 상태 전환 시 카드를 교체하거나 다른 위치에 렌더링하지 않고 같은 카드의 제목과 설명만 변경한다.

서버 접수 확인 전 문구:

- 제목: `녹화 파일을 업로드하고 있어요`
- 설명: `아직 서버에 안전하게 저장되지 않았어요. 잠시만 기다려 주세요. 새로고침하거나 페이지를 나가면 정보가 유실될 수 있어요.`

서버 접수 확인 후 문구:

- 제목: `분석 결과를 준비하고 있어요`
- 설명: `페이지를 이동해도 분석은 계속되며, 완료 후 내 기록에서 확인할 수 있습니다.`

## 이탈 방어

서버 접수 확인 전에는 Vue Router 이탈 가드와 브라우저 `beforeunload` 경고를 모두 적용한다. 분석 화면에서 뒤로가기나 다른 내부 경로 이동을 시도하면 기존 확인 모달을 표시한다.

서버 접수 확인 후에는 다음 동작을 적용한다.

- 라우터 이탈을 즉시 허용한다.
- `beforeunload`를 취소하지 않는다.
- 이탈 모달을 표시하지 않는다.
- 이탈 모달이 열린 사이 서버 접수가 확인되면 모달을 닫고, 사용자가 이미 요청한 목적지로 이동한다.

사용자가 서버 접수 전에 모달에서 강제 이탈을 선택하면 현재 발표 흐름과 클라이언트 전용 녹화 데이터를 폐기하고 요청한 목적지로 이동한다.

## 질문 생성 및 질의응답 새로고침

발표 녹화를 시작한 시점부터 서버 접수 완료를 확인할 때까지 새로고침 복구 마커를 유지한다. 녹화 화면을 정상 종료해 질문 생성이나 질의응답 화면으로 이동할 때 이 마커를 지우지 않는다.

질문 생성 화면과 질의응답 화면에서는 다음 동작을 적용한다.

- 새로고침·탭 닫기 시 브라우저 기본 `beforeunload` 경고를 표시한다.
- 사용자가 경고를 무시하고 새로고침하면 메모리 Blob이 유실된 것으로 판단한다.
- 발표 Store와 녹화 Store를 초기화하고 새로고침 복구 마커를 제거한다.
- 홈에 일회성 종료 안내를 예약하고 홈으로 이동한다.
- 일반적인 분석 화면 → 질의응답 화면 내부 이동에서는 세션과 마커를 유지한다.

서버 접수 완료가 확인되면 새로고침 복구 마커를 제거한다. 이후 분석 화면 새로고침은 서버 상태 폴링을 재개할 수 있으며 세션 폐기 대상으로 처리하지 않는다.

## 오류 처리

- `/complete` 실패: 업로드 미완료 상태를 유지하고 기존 실패 안내를 표시한다.
- 첫 유효 상태 확인 전 상태 조회 실패: 업로드가 안전하게 접수됐다고 가정하지 않는다.
- `FAILED`: 서버 분석 실패 안내를 표시한다.
- 알 수 없는 상태: 완료로 간주하지 않고 명시적인 오류로 처리한다.

오류 상태에서 자동 재업로드나 자동 리포트 재생성은 이번 범위에 추가하지 않는다.

## 테스트

다음 회귀 시나리오를 자동 테스트한다.

1. `/complete` 요청 중에는 업로드 안내 카드가 보이고 라우터 이탈과 `beforeunload`가 차단된다.
2. `/complete`가 반환돼도 첫 유효 `/status` 응답 전에는 이탈 방어가 유지된다.
3. `PENDING`을 확인하면 동일 카드의 문구가 백그라운드 분석 안내로 바뀐다.
4. `PENDING` 이후에는 라우터 이탈과 새로고침이 허용된다.
5. 이탈 모달이 열린 상태에서 `PENDING`을 확인하면 요청했던 경로로 이동한다.
6. 상태 조회는 `/presentations/{presentationId}/status` 계약을 사용한다.
7. 질문 생성 또는 질의응답 화면을 새로고침하면 발표·녹화 상태를 초기화하고 홈으로 이동한다.
8. 정상적인 질문 생성 → 질의응답 이동에서는 세션이 유지된다.
9. 관련 Vitest 전체와 Vite 프로덕션 빌드가 성공한다.

사용자 요청에 따라 실제 브라우저를 이용한 UI 검증은 수행하지 않는다. 렌더링 동작은 Vue 컴포넌트 테스트로 검증한다.
