# 홈·학습 추이·회원 정보·업로드·공유 개선 설계

## 목표

사용자가 제보한 일곱 가지 프런트엔드 문제를 기존 Vue 3, Pinia, Vue Router 구조 안에서 해결한다. 백엔드 계약은 변경하지 않으며 발표·면접 녹화 및 리포트 분석 동작에도 영향을 주지 않는다.

## 범위

1. 내 학습 추이의 잘못된 조사 표현을 수정한다.
2. 점수 그래프를 0점부터 100점까지 고정된 세로축에 표시하고 그래프 높이를 소폭 늘린다.
3. 홈페이지 Script 영역의 이전·다음 버튼으로 예시 슬라이드를 순환 탐색할 수 있게 한다.
4. 회원 닉네임과 프로필 이미지가 로그인, 새로고침, 프로필 수정 직후 모든 표시 영역에 반영되게 한다.
5. 발표 자료를 선택했을 때 보이는 `업로드 대기` 문구를 제거한다.
6. 발표 자료와 자소서·포트폴리오 PDF 업로드 제한을 모두 50MB로 통일하고 화면에 표시한다.
7. `https://aivo.ai.kr/` 링크 공유 시 제목, 설명, 대표 이미지가 표시되도록 정적 메타데이터를 추가한다.

## 설계

### 1. 학습 추이 문구와 점수 그래프

`MyPageTrendView.vue`의 다음 연습 추천 문구는 지표 이름 뒤에 `를`을 무조건 붙여 `슬라이드 내용 전달를` 같은 표현을 만든다. 조사 판별 로직을 추가하는 대신 모든 지표에 자연스러운 `${지표명} 지표를 먼저 개선해 보세요.` 형식을 사용한다.

점수 그래프는 데이터의 최솟값과 최댓값으로 세로 위치를 재계산하지 않는다. 유효 점수는 기존 정규화 단계에서 0~100 범위로 제한되므로, 그래프 좌표는 고정된 상단 100점과 하단 0점 사이에서 `점수 / 100` 비율로 계산한다. 왼쪽에 100, 75, 50, 25, 0 레이블과 대응 수평 기준선을 표시한다. 기존 이전 3회·최근 3회 구분선, 선 색상, 점수 레이블과 선택 버튼은 유지한다. SVG 표시 높이는 데스크톱 기준 185px에서 약 215px로 늘리고 모바일도 같은 비율로 소폭 확대한다.

### 2. 홈페이지 Script 탐색

`HomeView.vue`의 썸네일과 이전·다음 버튼은 동일한 `scriptSlide` 상태를 사용한다. 이전·다음 함수는 현재 항목의 인덱스를 기준으로 이동하고 처음과 끝에서는 반대편으로 순환한다. 두 버튼의 `aria-disabled`와 음수 tabindex를 제거하고 실제 클릭 가능한 버튼으로 제공한다. 버튼을 누르면 슬라이드 이미지, 제목, 대본이 함께 변경된다.

### 3. 회원 정보 동기화

`authStore`를 사용자 정보의 유일한 표시 원본으로 유지한다.

- 로그인 성공 직후 임시 사용자 정보를 먼저 저장한 다음 `/users/me`를 조회해 닉네임과 프로필 이미지를 채운다. 프로필 조회 실패가 로그인 성공 자체를 취소하지는 않는다.
- 저장된 인증 정보로 앱을 다시 열었을 때 앱 초기화 과정에서 `/users/me`를 한 번 조회한다. 실패하면 저장된 사용자 정보를 유지한다.
- 프로필 수정 응답은 현재 사용자와 병합해 즉시 Store에 반영한다. 이후 `/users/me`를 다시 조회해 presigned 이미지 URL을 포함한 최종 서버 값을 동기화한다. 재조회 실패 시 이미 반영한 수정 응답은 유지한다.
- 프로필 이미지 갱신 revision은 수정 응답과 최종 조회 모두에서 유지해 같은 경로가 반환되더라도 이미지 엘리먼트가 새 identity를 사용하게 한다.

홈페이지 닉네임과 공통 헤더는 이미 Pinia의 반응형 값을 읽고 있으므로 별도 복제 상태를 만들지 않는다.

### 4. 업로드 상태와 50MB 제한

발표 자료는 파일을 선택해도 실제 전송이 다음 버튼에서 시작된다. 선택 직후에는 파일명과 용량만 표시하고 `업로드 대기` 문구는 표시하지 않는다. 처리 중, 완료, 실패 상태 문구는 그대로 유지한다.

발표 자료의 `MAX_PRESENTATION_FILE_SIZE`를 50MB로 변경하고 오류 문구와 업로드 영역 안내를 `최대 50MB`로 통일한다.

자소서·포트폴리오는 별도의 공통 PDF 검증 유틸리티를 사용한다. 유틸리티는 파일 존재 여부, PDF 확장자·MIME, 0바이트, 50MB 초과를 검증한다. 마이페이지 등록 화면은 이 검증 결과를 바로 보여주고 파일 입력 영역에 `PDF · 최대 50MB`를 표시한다. `documentsStore.uploadDocument`도 같은 검증을 수행해 화면 검증을 우회한 직접 호출이 서버에 전송되지 않게 한다.

50MB는 기존 코드와 동일하게 `50 * 1024 * 1024` 바이트로 정의한다. 정확히 50MB인 파일은 허용하고 그보다 1바이트라도 크면 거부한다.

### 5. 링크 공유 메타데이터

Vite SPA 진입점인 `index.html`에 다음 정적 정보를 추가한다.

- canonical URL: `https://aivo.ai.kr/`
- 한국어 서비스 설명
- Open Graph: `og:type`, `og:site_name`, `og:locale`, `og:title`, `og:description`, `og:url`, `og:image`, 이미지 크기와 대체 텍스트
- Twitter Card: `summary_large_image`, 제목, 설명, 이미지

대표 이미지는 현재 공개 폴더에 있고 HTTPS로 접근 가능한 `https://aivo.ai.kr/home-presenter.png`를 사용한다. SPA의 클라이언트 라우팅 후 메타데이터 변경은 크롤러가 실행하지 않을 수 있으므로 이번 범위에서는 모든 공유 링크의 기본 카드만 제공한다.

## 오류 처리

- 회원 정보 자동 동기화 실패는 기존 로그인 상태와 저장된 사용자 정보를 제거하지 않는다.
- 프로필 PATCH 성공 후 최종 GET만 실패한 경우 수정 자체를 실패로 표시하지 않는다.
- 지원 자료 파일 검증 실패 시 API를 호출하지 않고 사용자가 수정할 수 있는 구체적인 오류 문구를 표시한다.
- 점수 값이 없으면 기존처럼 해당 점을 그리지 않는다.

## 테스트 및 완료 기준

- 문구 테스트에서 `전달를`이 없고 `지표를 먼저 개선해 보세요`가 표시된다.
- 0점, 50점, 100점이 각각 고정된 하단, 중앙, 상단 좌표에 표시되고 축 레이블 5개가 렌더링된다.
- 홈페이지 이전·다음 버튼이 슬라이드와 대본을 변경하며 양 끝에서 순환한다.
- 로그인, 앱 초기 동기화, 프로필 수정 응답과 후속 조회가 Store의 닉네임·프로필 이미지를 갱신한다.
- 발표 자료 선택 직후 `업로드 대기`가 표시되지 않는다.
- 발표 자료와 지원 PDF는 정확히 50MB까지 허용하고 초과 파일은 UI와 Store에서 거부한다.
- `index.html`에 `https://aivo.ai.kr/` 기준 canonical, Open Graph, Twitter Card가 존재한다.
- 관련 Vitest, 전체 테스트, 프로덕션 빌드가 통과한다.
- 개발 서버에서 홈페이지 Script 버튼을 실제 조작하고, 접근 가능한 화면의 레이아웃과 콘솔 오류를 확인한다.

## 비범위

- 백엔드 파일 제한과 Nginx `client_max_body_size` 변경
- 동적 라우트별 Open Graph 카드 생성 또는 SSR 도입
- 새 공유 이미지 제작
- 면접 답변·자막·리포트 분석 로직 변경
- 차트 라이브러리 도입
